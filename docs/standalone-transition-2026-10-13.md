# OpenVote 독립 서비스 전환 계획 (2026-10-13)

## 결정 및 범위

사용자 지시:
1. OpenVote 회원은 노조링크·Cowork·Scrizzle 회원과 **가입 자격·로그인 신원·권한을 공유하지 않는다**.
2. 노조링크 연동은 잠정 중단한다. 기존 데이터/연동 SQL/코드를 파괴적으로 삭제하지 않는다.
3. OpenVote 자체에서 가입 → 투표 생성 → 초대 → 무기명 투표 → 종료·검증을 운영한다.
4. 브랜드명은 최종 선택 전까지 **기존 내부 이름을 유지**한다.

### 가입/로그인 독립성의 정확한 뜻

동일 Supabase 프로젝트 사용 = 반드시 공동 회원 운영을 의미하지 않는다.
Cowork는 자체 `cw_users`와 자체 Google OAuth→합성 메일 계정, Scrizzle은 `sz_google_accounts`와 별도 Google OAuth→합성 메일 계정을 사용한다.

OpenVote 1.0 권장:
- 자체 `app_open_vote.members`(또는 `accounts`)에 사용자 식별/상태/역할/가입일/표시 이메일을 보관한다.
- 로그인 식별키는 타 서비스의 `auth.users` 행/이메일로 합치지 않는다. Google OAuth를 도입하면 OpenVote 고유 client_id·서버 검증·불변 Google `sub` 기반으로 전용 합성 메일 계정을 발급한다. shared GoTrue `signInWithOAuth`·`linkIdentity`를 호출하지 않는다.
- 이메일/비밀번호 가입이 반드시 필요하면 **독립적으로 식별되는 회원 자격·자체 확인 절차·복구 수단**을 설계한다. 현재 공유 SMTP는 꺼져 있어 `signUp` + 매직링크를 연결한다고 가입이 운영되는 것이 아니다.
- 유권자는 초대된 투표 토큰으로 참여하며 서비스 회원가입을 요구하지 않는다.
- 기존 `unionk25@gmail.com`의 **공유 로그인 신원 자체**를 관리자 로그인으로 재사용하지 않는다. 독립 가입 후 소유자 증명을 거쳐 새 앱 계정에 admin을 부여한다.
- 다른 앱의 `auth.users`·`auth.identities`·`app_metadata.role`·토큰 훅·SMTP·OAuth provider 설정은 변경하지 않는다.
- 타 앱에서 발급된 토큰으로 OpenVote 관리 API에 접근해도 자체 회원 표의 자격이 없으면 반드시 403을 준다.
- 계정 생성과 회원행 기록의 원자성/중단복구, 탈퇴 후 과금 원장 보존, 가입·로그인 남용 방지(rate limit), 개인정보 최소 수집을 검토한다.

### 관리자/사용자 권한

- `pending`: OpenVote 자체 가입은 했으나 투표 생성 권한 없음.
- `creator`: 본인 선거 생성·관리와 자기 지갑.
- `admin`: 모든 선거·creator 승인·포인트 지급·감사 기록.
- 권한 판정은 OpenVote 전용 서버측 DB 조회로 통일한다. 클라이언트의 `app_metadata.role`은 OpenVote 관리자 판단 근거로 사용하지 않는다.
- server routes `requireAdmin`, `requireVoteCreator`, `canManageElection` 및 클라이언트 `AdminGate`를 동시에 교체한다.
- 서버 전용 조회(서비스 롤)는 신원 확인·회원 자격·선거 소유권을 **각 요청에서** 다시 검증한다.
- 관리자 최초 생성은 엄격한 수동 승인/일회성 부트스트랩(대상 계정 확인, 실행 로그 기록, 반복실행 방지)으로 한다. 첫 회원 자동 승격 금지.
- 별도 대의원/선거관리자의 범위를 장래 조직 단위로 확장 가능하게 한다.

### 노조링크 연동 중단 — 로컬 구현됨, 아직 미배포

`OPENVOTE_ENABLE_NOZOLINK_INTEGRATION`의 기본값은 disabled. 값이 정확히 `true`일 때만 열림.
- `/api/v1/elections` 및 관련 선거 조회/종료/수정/삭제/투표여부 조회
- `/api/v1/wallet`
- `/auth/handoff` (토큰 검증 컴포넌트를 렌더링하지 않음)
- 조합 지갑 API `/api/admin/credits`
- 새로운 외부 연동 API 키 발급 제한, 기존 키는 비활성화만 가능
- 관리 화면에는 개인 선거용 포인트 지급만 노출

주의: 코드를 배포하기 전 운영 서비스는 기존 동작 그대로다.
노조링크 측 기존 링크·투표 버튼에는 중단 안내가 필요하나, 노조링크 소스는 이 작업에서 수정하지 않는다. 연동 중단은 **코드 배포/운영 DB 권한 복구와 별도 승인**이 필요하다.
중단 자체는 외부 API 키를 삭제하거나 기존 연동 데이터를 삭제하지 않는다.

### 보안/DB 선결 과제

2026-10-12 읽기 검증:
- 운영 `app_open_vote.elections`: 0행; 기존 사용자 50명 중 `app_metadata.role` 기준 admin/creator는 각각 0.
- 운영 DB에는 `ballots.sequence_number`와 공개 SELECT/Realtime가 남아 있어 최신 기능 브랜치 마이그레이션(`20261010000000_ballot_types_and_secrecy.sql`)과 불일치한다.
- 회원 기능만 추가해도 **실제 선거를 개시하면 안 된다**. 별도 DB 복사본에서 마이그레이션 검증 → 승인 후 운영 적용.
- 신규 회원/권한 관련 스키마 변경은 `app_open_vote` 한정, 필요 테이블 RLS 및 최소권한, 허용 role grant 0 기준선 유지.
- GoTrue 기능을 이용할 경우 공유 인증 자원 영향 재검증, 독립 프로젝트 비용·운영 복잡성은 필요할 때만 검토.

### 구현 순서

1. **현재까지:** 외부 연동 라우트 기본 중단·관리 UI 연동 조합지갑 숨김·검증 테스트. 임시 인가 방어로 공용 `app_metadata.role`만 가진 타 서비스 계정은 거부하고 `app_metadata.app = 'open_vote'` 계정만 허용하도록 변경(최종 DB 회원 권한 설계로 대체 예정). 공용 DB와 타 서비스는 무수정.
2. **회원 가입**: OpenVote 전용 가입 자격 테이블·OAuth 계정 연결 표·서버 API, 가입·로그인·로그아웃 및 실패 복구. 필요한 전용 Google OAuth 클라이언트/Edge Secret은 사용자 승인 및 설정 선행.
3. **권한 교체**: admin/creator 검증 경계 서버측 일원화, 관리자 승인 UI, 개인 포인트 지갑 연결 및 포인트 지급을 OpenVote 회원 인덱스로 조회하도록 변경.
4. **투표 통합**: 스키마/서버 API 호환, 생성→draft→active→SMS→1회 기표→closed, 투표 종료 전 결과 차단, 감사 로그.
5. **테스트**: 다른 앱에 동일 이메일로 가입해도 회원/세션/권한 분리되는지, 타 앱 토큰 API 권한 차단, 관리자 승격 위조 방어, 문자 오발송 없음, 비밀투표 독립 검증.
6. **승인 후 운영**: 필요한 SQL만 적용, 배포, 제한된 시험 유권자 E2E, 정리 후 본 선거.

### 반드시 통과할 테스트

- 신규 OpenVote 회원은 다른 앱의 member row를 만들거나 변경하지 않는다.
- 동일 Google 계정으로 타 앱을 쓰더라도 OpenVote 회원 계정 ID는 별개이며 소셜 신원 충돌이 없다.
- 처음 가입한 사용자가 스스로 admin/creator로 승격할 수 없다.
- 실제 `unionk25@gmail.com`로 새 OpenVote 앱 계정 가입 후 인증·admin 수동 지정·관리자 로그인 가능.
- 기존 연동 API는 플래그 미설정일 때 일관되게 410, DB 쓰기/문자 발송에 도달하지 않는다.
- `/admin` 페이지와 POST `/api/elections`의 creator 권한이 일치한다.
- 익명 투표 데이터가 클라이언트 직접 조회/Realtime에 노출되지 않는다.
- 선거 종료 후 누가 어떤 후보를 골랐는지 관리자도 추적할 수 없다.
- 모의 발송→승인된 테스트 번호 실발송, 고의적 재발송과 링크 무효화, 기간만료/중복 투표 차단.

### 브랜드 변경 범위 (확정 전 미변경)

1. **화면 표시명만**: app-frame 헤더·홈·메타정보·안내문·문자 템플릿 — 소수 파일, DB 스키마·Git·도메인 유지.
2. **서비스 공개 브랜드/도메인도 변경**: 1 + Vercel 도메인, DNS, 발신 SMS URL, 로그인 콜백 허용 origin, 개인정보처리방침, 북마크/기존 초대 링크 호환/리디렉션.
3. **내부 코드 이름까지 전부 변경**: 2 + 저장소명, 프로젝트 폴더, npm 패키지, `ovk_` 키 접두사, `app_open_vote` 스키마 및 연동 RPC/마이그레이션 전수. 비용·위험 크므로 **권장하지 않음**.

2026-10-13 조사: OpenVote 이름은 기존 선거 서비스와 직접 겹침; OnVote도 Web3 투표 쪽 선사용 흔적 존재; Votely는 이미 다양한 서비스에서 사용. 대안 이름은 국내 KIPRIS와 상용 도메인 최종 확인 필요.

### 미완료 / 승인 필요

- **회원가입 기능은 아직 구현되지 않았다.** 독립 신원·관리자 가입 방식을 확정하고 로컬 구현·통합 검증해야 한다.
- 운영 계정 관리자 권한 부여, 운영 DB 마이그레이션, Vercel 배포, SMS 실발송, 리포지토리 커밋/푸시는 실행하지 않았다.
