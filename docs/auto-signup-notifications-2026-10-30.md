# 가입 즉시 사용·구글챗 알림·안내 개선 (2026-10-30)

## 동작

- 구글 가입 시 `creator`로 등록한다. 기존 `pending`도 생성자로 전환했다. `admin`·`suspended`는 유지한다.
- 이메일·비밀번호 로그인 화면을 제거하고 기존 로그인 API는 410으로 종료한다. 기존 회원 행이나 공유 Auth 계정은 삭제하지 않는다. 확인된 같은 구글 이메일로 기존 회원을 연결하는 경로는 유지한다.
- `/admin/manage`의 ‘알림 관리’에서 전체·회원 가입·투표 생성·모든 투표 접수를 각각 켜거나 끈다. 알림 목록과 설정 API는 관리자만 접근한다.
- DB 삽입 트리거가 알림함을 함께 기록한다. 기표가 롤백되거나 중복 기표가 거부되면 접수 알림도 생기지 않는다. 과거 사건은 소급 생성하지 않는다.
- 구글챗에는 가입 사실, 선거 제목, 생성·접수 사실, 알림 번호만 전송한다. 가입자의 이메일·이름, 투표자 전화번호·IP·선택·자격·영수증·기표지 식별자는 포함하지 않는다.
- 설정을 끈 동안에도 관리자 목록에는 ‘발송 안 함’ 기록을 남긴다. 발송 중인 HTTP 요청은 취소를 보장하지 않는다.

## 발송과 비밀 설정

서버 전용 `GOOGLE_CHAT_WEBHOOK_URL` 환경변수를 사용한다. URL은 DB·브라우저·로그에 노출하지 않는다. HTTPS `chat.googleapis.com`의 정규 webhook 경로만 허용한다. 웹훅이 없으면 사건을 목록에 보관하고 외부 요청은 하지 않는다.

사용자가 지목한 상위 `.env`는 확인 당시 0바이트여서 웹훅을 설정하지 못했다. 사용자에게 해당 파일에 값을 저장하도록 요청했다. 실제 구글챗 수신 확인은 미실시다. 값이 준비되면 로컬·Vercel 환경에 안전하게 등록한 뒤 다시 배포한다. 채팅이나 소스에 주소를 복사하지 않는다.

가입·생성·기표 성공 응답 후 Next `after`로 처리한다. 발송 오류는 원래 동작을 취소하지 않는다. 실패 시 최대 5회 지수 지연 재시도하며 다음 사건, 관리자 ‘대기 알림 처리’, 일일 cron에서 다시 처리한다. 관리자 목록 조회는 자동 폴링하지 않는다.

Google Chat 공간별 초당 1건 제한 때문에 DB의 전역 발송 임대로 인스턴스 간 동시 발송을 막고, 최소 1.1초 간격으로 순차 처리한다. 한 번에 10건을 예약하며 응답 후 작업은 최대 20묶음·시간 예산 내에서 대기를 비운다. 작업 중단 시 임대 만료 후 다시 처리한다. 오래 대기한 알림은 실시간 도착을 보장하지 않으며 관리자 목록에서 확인할 수 있다. 응답 유실 직후에는 같은 알림이 중복 도착할 수 있어 알림 번호를 붙인다. 외부 웹훅은 정확히 한 번 전달을 보장하지 않는다.

참고: [Google Chat 웹훅 공식 문서](https://developers.google.com/workspace/chat/quickstart/webhooks).
