# 모아이투표 v0.9 — 무인 운영과 증거 기반 공개 검증 계획

> **최신 확정 계획:** [v1.0 기존 서비스 기반 경량 감사 계획](voting-native-audit-plan-2026-10-28.md)이 우선한다. Belenios 도입과 운영자 비신뢰 B-1 연구는 보류하고, 기존 모아이에 표준 해시·서명·숨김 약정·공개 집계 재검증을 추가한다. 아래는 과거 검토 기록이며 현재 구현 완료를 뜻하지 않는다.

- 작성: 2026-10-28
- 목적: 일상적인 단체 의사결정을 간편하게 운영하면서, 운영자가 규칙·접수 기록·집계의 일치를 재검증 가능한 자료로 제시하게 한다.
- 상태: 계획 작성. Belenios 설치·실행, 기능 구현, 운영 DB 변경, 실제 문자 발송, 외부 게시·배포는 하지 않았다.
- 우선순위: [v0.8 제품 결정](voting-product-decision-2026-10-28.md)과 이전 v0.3~v0.7 연구 문서보다 이 계획을 우선한다. Belenios 최소 도입 평가를 재개하되, 운영자 비신뢰 B-1 모델은 현재 목표로 복원하지 않는다.

## 1. 제품 목표와 신뢰 범위

**운영자를 일정 부분 신뢰하면서, 운영자가 설명해야 할 내용을 자료와 검증 절차로 남기는 서비스**로 만든다. ‘부정이 전혀 없었다’는 인증서를 발급하지 않는다.

| 구분 | 제공할 확인 | 한계 |
|---|---|---|
| 규칙 | 시작 시 고정한 후보·선택 규칙·정원·마감·인증 정책과 최종 자료의 일치 | 시작 전 받은 독립 사본이 없으면 서버의 전체 재작성까지 배제하지 못함 |
| 적격 형식 | 공개 자격 목록에 속하는 유효 서명·증명의 투표지인지 | 운영자가 만든 자격이 실제 사람의 의사로 사용됐는지는 증명하지 못함 |
| 중복 | 1인 1회 정책에 맞는 공개 자격 사용 여부 | 명부를 조작해 서로 다른 자격을 만든 유령 표는 별개 |
| 접수 | 참여자가 보관한 기록의 포함과 서버의 접수 승인 서명 | 잘못된 웹 코드가 의도와 다른 표를 만든 문제는 포함 검사만으로 잡지 못함 |
| 이력 | 보관한 기준점에서 최종 원장까지 연결되는지 | 비교되지 않은 분기·보관 이전 변경은 남음 |
| 집계 | 정확한 공개 암호문 집합의 집계·복호화 증명과 발표 결과의 일치 | 실제 유권자가 강요 없이 선택했는지, 비밀이 몰래 유출되지 않았는지는 증명하지 못함 |
| 문자 인증 | 설정 선언과 서버 운영 점검 | 공개 투표 자료만으로 모든 OTP 절차의 실제 이행을 증명하지 못함 |

일반 이용자·선거 생성자에게 개별 선택을 명부와 연결하는 화면/API/내보내기를 제공하지 않는다. 브라우저에서 선택을 암호화하되, 자동 운영에 필요한 비밀 자격·복호화 키를 운영자가 통제하므로 운영자 대상의 암호학적 비밀성은 보장하지 않는다. 악성 웹 JS·키 접근·백업·공모 위험을 수용 범위에 명시한다.

## 2. 최소 도입 구성

```text
모아이: 회원·선거 생성·명부·문자·포인트·상태/결과 안내
  ├─ Belenios: 원형 기표 화면·자격/증명 검사·암호화 기록·집계
  ├─ 자동 작업자: 생성/개시/마감/집계/공식 검증/자료 공표
  └─ 읽기 전용 증거 어댑터: 원장 확인·접수 증언 서명·보고서

참여자/주최자: 시작 규칙·확인증·공개 검증 묶음 독립 저장
외부 검증: 공개 묶음 + 고정 버전 공식 CLI + 모아이 정책 검사
```

- 기존 모아이의 회원·과금·명부 서비스는 유지한다. 새로운 표의 원본과 집계 입력은 Belenios로 일원화한다. 모아이 DB에 선택 평문을 중복 저장하거나 별도 결과 집계를 만들지 않는다.
- Belenios는 별도 지속 실행 서비스로 평가한다. Vercel 요청 함수 안에 엔진·장기 작업·키 파일을 넣는 구성을 전제하지 않는다. 실제 호스트·자원은 격리 측정 후 결정하며 공용 서버를 지금 변경하지 않는다.
- 첫 도입은 원형 기표 화면으로 이동하고 로고·색상·안내만 조정한다. 암호 기표 코드를 모아이 TS로 포팅하지 않는다.
- 자격 생성·전달·서버 집계 키 관리는 자동화한다. 외부 발급자나 사람이 매번 참여하는 키 의식은 요구하지 않는다. 작업자와 앱의 권한은 분리하되 같은 운영자 통제이므로 독립 주체라고 부르지 않는다.
- Belenios의 원형 이벤트 체인을 사용한다. v0.8의 평문 원장+숨김 약정 체인 안을 병행 구현하지 않는다. 기존 선거의 저장 형식·영수증·결과는 유지하고 새 엔진 선거와 식별한다.
- 새 엔진 선거에는 기존 평문 기표 API나 비상 대체 집계 경로를 연결하지 않는다. 엔진 장애 시 같은 선거를 현행 엔진으로 조용히 전환하지 않는다.

공식 README는 서버가 자격 발급자와 보관자 역할까지 맡는 단순 구성을 설명한다. 그 구성이 독립 역할 분리보다 약하다는 점도 함께 명시한다. 이는 기능 지원 근거이며 자동화 API·복구 동작을 실증한 결과는 아니다. [공식 README](https://raw.githubusercontent.com/glondu/belenios/master/README.md)

## 3. 고정 규칙과 초기 지원 범위

첫 도입은 단일 선택·다중 선택·항목별 찬반으로 한정한다. 질문별 최소/최대·기권과 투표지 전체 기권이 정확히 일치하는 설정만 제공한다. 기존 순위 기능은 현행 엔진에서 유지하고 새 엔진 순위 지원은 보류한다.

시작 고정본에는 선거 ID, 엔진/암호/자료 형식 버전, 질문·후보 ID와 순서, 선택/기권 규칙, 정원, 공개 자격 목록 digest, 재투표 금지, 개시·마감, 문자 인증 여부, 결과 공개 기한, 집계 공개키, 접수 증언 공개키를 포함한다. 개인정보 명부를 공개하지 않는다. 전화번호·이름의 단순 해시 목록을 공개 명부로 대체하지 않는다.

1인 1회는 접수 설정과 전체 Ballot 이력의 정책 검사를 함께 적용한다. 동일 기표문의 통신 재시도는 새로운 투표로 만들지 않는 방향으로 검증한다. 다른 기표문을 같은 자격으로 받지 못하게 해야 한다. 원형 엔진의 ‘마지막 표 집계’가 검증을 통과해도 모아이 정책 위반이면 별도 실패로 보고한다.

시작 이후 규칙·자격 목록·마감·필수 인증의 변경은 거부한다. 불가피한 정정은 시작 전 수행하고, 개시 후 문제가 생기면 명시적으로 취소 후 새 선거를 만든다. 마감된 선거를 다시 열지 않는다.

실명 명부 수·공개 자격 수·최종 사용 자격 수·집계 입력 수는 각자의 의미로 비교한다. 같은 표의 재시도나 비투표 이벤트를 새 유효표로 세지 않는다. 모아이 인증/명부의 집계 수와 엔진 수가 다르면 조정 대기로 남긴다. 운영자가 양쪽 수를 함께 조작할 수 있으므로 수 일치만으로 유령 표 부재를 증명했다고 쓰지 않는다.

## 4. 접수 확인증과 과거 기준점

Belenios tracker는 암호화 투표지 식별값으로 사용한다. 이것만으로 서버가 당시 접수를 승인했다는 서명 증거가 된다고 설명하지 않는다. 공식 안내는 tracker를 보관하고 공개된 접수 표와 대조하는 절차를 설명한다. [참여자 안내](https://www.belenios.net/instructions.html)

모아이의 읽기 전용 어댑터는 다음 조건을 만족한 뒤 별도 접수 확인증을 발급한다.

1. 실제 엔진의 확정 공개 자료에서 해당 Ballot 이벤트와 tracker를 찾아 원본 바이트·이벤트 연결을 검사한다.
2. 선거 fingerprint, 규칙 고정본 digest, tracker, 이벤트 식별값/높이, 해당 원장 기준점, 형식 버전·발급 키 ID를 한 페이로드로 결합해 서명한다.
3. 브라우저는 자신이 제출한 기표문의 tracker와 발급 자료·서명을 확인하고 파일 저장을 제공한다.
4. 확인증은 **모아이 발급자가 원형 기록을 확인하고 서명한 별도 증언**임을 표시한다. Belenios가 원래 서명한 영수증으로 표현하지 않는다. 개인 이름·전화번호·IP·비밀 자격·암호화 난수는 넣지 않는다.

어댑터는 별도 체인을 만들거나 표를 재작성하지 않는다. 엔진 접수 후 서명 실패는 ‘접수됨·확인증 준비 중’으로 구분한다. tracker로 공개 접수 상태를 확인하고 동일 이벤트의 서명 자료를 재조회할 수 있게 한다. 확인증이 없는데 발급 완료로 표시하지 않는다. 확인증 생성·검증은 신규 개발이며 원형 기능으로 이미 제공된다고 가정하지 않는다.

개인 파일에는 암호화 난수를 기본 저장하지 않는다. ‘내 암호화 기록 포함’과 ‘내 선택대로 암호화됨’을 구분한다. 이전 평문 영수증 시제품을 새 엔진 확인증에 그대로 재사용하지 않는다. 짧은 코드는 표시용이며 비밀 복구나 소유 인증의 근거로 쓰지 않는다.

## 5. 외부 보관과 비교

- **시작 전:** 주최자가 고정본을 내려받아 보관·배포할 수 있게 한다. 전달본의 전체 digest와 공개키를 나중에 비교한다.
- **투표 중:** 작업자가 공개 archive를 주기적으로 가져와 원형 이력 검증을 수행하고 기준점을 보존한다. 주최자·참여자는 확인증과 공개 기준점을 별도 보관할 수 있다.
- **마감 후:** 최종 archive·규칙·집계/복호화 증명·서명된 최종 자료 목록·검증 보고서·검증 명령을 한 묶음으로 다운로드할 수 있게 한다. 그 사본만으로 서버에 접속하지 않고 재검증 가능해야 한다.

운영자 계정의 별도 스토리지는 복구 사본일 뿐 독립 증거로 계산하지 않는다. 외부 보관은 주최자·참여자가 통제하는 사본부터 시작한다. 다른 주체의 자동 미러는 이후 선택 기능으로 둔다. 독립 사본이 없는 선거도 운영할 수 있지만 보고서에는 `EXTERNAL_ANCHOR_UNCONFIRMED`로 남긴다. 다운로드 버튼 제공·운영자 내부 보관만으로 외부 보관이 완료됐다고 쓰지 않는다.

확인증·독립 사본과 최종 이력이 양립하지 않는 유효 서명이 발견되면 관련 원본·서명·키·비교 기준을 담은 충돌 보고서를 만든다. 네트워크 장애·자료 부족을 서명 충돌로 단정하지 않는다. 키 침해나 운영 오류 등 원인 판정은 별개다.

## 6. 선택형 문자 인증과 참여 여부 확인

생성자가 ‘제출 전 휴대폰 문자 인증’을 선택한다. 기본값 해제이며 기존 자격·1회 투표 검사는 항상 적용한다. 필수 선거는 확정 단계에서 등록 번호의 새 인증을 요구한다. 외부 인증 연결의 실제 시점·세션 수명·직접 API·관리자 경로를 시험하며, 안전하게 강제할 수 없으면 그 옵션이 필요한 선거는 새 엔진으로 개시하지 않는다.

새 블라인드 토큰이나 암호문 digest-전화번호 매핑 저장소를 만들지 않는다. 문자에는 인증번호와 최소 안내만 넣고 선거 제목·비밀 자격은 넣지 않는다. 자격 전달이 같은 운영 인프라를 거치는 최소 구성은 허용하되 독립 발급·운영자 도용 방지라고 설명하지 않는다. 링크에 자격을 포함하는 방식의 URL·분석 도구·오류 기록 유출도 시험한다.

모의 발송에서 재발송 대기·검증 횟수·발송 예산·중복 과금·인증 전후 전송 실패를 검사한다. 번호 임의 입력·개시 후 관리자 예외·자동 인증 생략을 제공하지 않는다. 마감은 고정하며 통신 지연으로 자동 연장하지 않는다. 실제 발송과 수신·과금 확인은 별도 검증 대상으로 남긴다.

유권자가 자기 인증 수단으로 **투표권 사용 여부만** 확인하는 화면을 제공한다. 선택·공개 기록 위치는 함께 반환하지 않는다. ‘나는 투표하지 않았음’ 이의 제기를 받을 수 있게 하되, 신고는 도용 확정 증거가 아니며 서버 응답 자체도 독립 증명은 아님을 명시한다. 대량 유료 통지를 기본으로 추가하지 않는다.

## 7. IP와 개인정보 취급

IP를 투표지·확인증·공개 원장에 넣지 않는다. IP는 실제 사람의 의사나 유령 표 부재의 증명이 아니다. 첫 도입에서 투표 감사를 명목으로 IP 영구 저장을 새로 만들지 않는다.

남용 방어에 필요한 접속 정보는 선택 평문·비밀 자격·tracker와 결합하지 않는 별도 보안 처리로 제한한다. 메모리 기반 제한을 우선 검토하고 보관이 필요하면 목적·최소 필드·권한·기간을 명시한다. 이름·전화번호·세션·OTP·URL 비밀·요청 본문을 공개 자료나 오류 수집에 넣지 않는다. 프록시·엔진·발송 제공자·백업·원형 로그의 기본값도 점검한다.

새 엔진은 암호문 순서를 가질 수 있으나 명부-표 대응을 일반 API에 노출하지 않는다. 기존 평문 ballots의 시각·순번·명부 ID 금지 규칙을 완화하지 않는다. 프로젝트 규칙과 새 엔진 자료의 경계는 구현 전 문서화한다.

## 8. 무인 작업과 장애 복구

```text
준비 → 설정 고정 → 개시 → 마감 → 집계 → 검증 → 결과/증거 공개
                     장애 시: 해당 단계 대기·재시도·운영 알림
```

각 단계의 성공 조건·멱등 키·잠금·재시작 복구를 정한다. 모아이 DB와 별도 엔진 사이의 분산 호출을 한 DB 트랜잭션이라고 가정하지 않는다. 엔진을 조회해 확정 상태를 조정하고, 불명확한 응답을 새 표·새 과금 요청으로 처리하지 않는다. 생성·자격 전달·접수·서명·집계·공표 단계별 장애를 주입한다.

마감 후 집계·서명·검증이 실패하면 공개 완료로 표시하지 않는다. 공개 기한 초과를 별도 실패 상태로 남긴다. 재시도는 같은 고정 최종 입력에 대해서만 수행하고 다른 집계본으로 바꾸지 않는다. 선거별 비밀 자격·집계 키·발급 서명키는 용도를 나누고 접근·백업·복구·폐기 정책을 둔다. 키의 ‘삭제’는 백업에도 적용되는지 확인하며 지워졌다는 운영 선언을 암호학적 사실로 표현하지 않는다.

자동 개표를 위해 운영자가 키를 보유하므로 마감 전 열람을 암호학적으로 막는다고 하지 않는다. 정상 서비스 경로에서는 마감 전 개별 표·중간 득표·개표 API를 차단한다. 키 유실 시 임의 결과를 만들지 않으며 복구 시험을 통과하기 전 자동 운영 완료로 판정하지 않는다.

## 9. 자동 검증 보고서

보고서에는 선거/규칙/최종 archive digest, 도구·엔진 버전, 재현 명령, 검사 범위, 아래 항목의 결과와 근거 파일을 포함한다. `PASS / FAIL / UNCONFIRMED / NOT_APPLICABLE`을 구분하고 단일 ‘부정 없음’ 도장을 찍지 않는다.

| 검사 | 근거와 표시 |
|---|---|
| 규칙 일치 | 시작 고정본·최종 규칙 비교. 독립 시작 사본 미확인은 별도 표시 |
| 자격 형식·투표지 증명 | 공식 검증기의 서명·증명 검사. 실제 사람의 진정한 의사 검증과 구분 |
| 1인 1회 | 원형 검증과 별도로 전체 Ballot 이력의 모아이 정책 검사 |
| 원장 이력 | 원형 연결·이전 사본과의 일관성 검사 |
| 개인 확인 | 사용자가 제시한 tracker/확인증에 대한 포함·서명·연결 검사. 확인증 미제출자까지 개인 검증됐다고 하지 않음 |
| 집계·결과 | 고정 최종 입력의 집계와 복호화 증명·화면 결과 비교 |
| 외부 사본 | 사용자가 가져온 독립 시작/이력/최종 사본과 비교한 범위 |
| 문자 인증 | `PRECAST_AUTH_DECLARED`: 설정 선언. 전원 실제 수행이 공개 검증됐다는 뜻 아님 |
| 자료·서명 이상 | `PROOF_UNAVAILABLE`, `PUBLICATION_OVERDUE`, `SIGNED_HISTORY_CONFLICT` 등을 구분 |

공식 도구 래핑 결과는 `BELENIOS_NATIVE_TOOL_VERIFIED`, 모아이의 별도 규칙/연결 검사는 `MOAI_POLICY_CHECKED`로 구분한다. 공식 코어를 다시 호출한 것을 독립 암호 구현 교차 검증이라고 하지 않는다. 공개 묶음·검증 도구/스크립트·사용 설명을 다른 사람이 받아 같은 검사를 실행할 수 있게 한다. 실제 공개·배포는 별도 작업이다.

공식 CLI의 `election verify` 등은 고정 버전의 실제 명령·입출력으로 확인하고 사용법을 묶음에 포함한다. 보고서 성공 문구를 다시 읽는 검사로 대체하지 않는다. [공식 CLI 문서](https://raw.githubusercontent.com/glondu/belenios/3.3.0/doc/tool.md)

사용자 화면은 ‘내 기록 확인’, ‘결과 계산 확인’, ‘검증 자료 다운로드’를 중심으로 간단히 만든다. 기술 상태는 상세에서 설명한다. 기본 문구는 **‘공개된 투표 기록과 결과의 일치를 확인할 수 있습니다’**로 하고 ‘모든 운영자 부정이 없었음을 증명’이라고 쓰지 않는다.

## 10. 구현 단계와 통과 조건

| 단계 | 작업 | 통과 조건 |
|---|---|---|
| P0 도입 적합성 | 버전/커밋·보안 변경·라이선스·자원·원형 API·정책 매핑 확인 | 알려진 위험의 적용 범위와 운영 가능 버전의 근거 확보. 설정으로 해결 못 하는 차이를 기록 |
| P1 원형 격리 실행 | 합성 명부·자동 자격·서버 키로 세 방식 개시/기표/마감/집계 | 원형 검증 통과, 질문·기권 매핑 일치, 코어 암호 변경 없음 |
| P2 무인 연결 | 상태 조정·재시도·마감·과금 경계·모의 OTP·직접 API 통제 | 중복·영구 접수 유실·필수 인증 우회 없음. 키/자료 복구 및 작업자 재시작 성공 |
| P3 증거 생성 | 읽기 전용 접수 서명·archive 스냅샷·최종 묶음·검증 보고서 | 접수 확인 없이 서명하지 않음. 외부 파일만으로 규칙/기록/결과 검사 재현 |
| P4 변조·실패 시험 | 아래 벡터·실제 모바일 크기/시간 측정 | 예상 판정 일치, 실패를 정상 완료로 표시하지 않음, 측정 전 고정한 UX 목표 충족 |
| P5 제품 반영 준비 | 안내·로그/백업 점검·운영 절차·소스 제공 정리 | 실제 보장과 UI 일치, 필요한 검사 통과 후 별도 DB/배포 절차 진행 |

필수 벡터:

1. 후보·선택 규칙·공개키 바꿔치기와 시작 사본 미확인을 각각 판정한다.
2. 미등록 자격·위조 서명·다른 선거 증명 재사용·무효 선택을 거부한다.
3. 같은 표 재전송·같은 자격의 다른 표·직접/관리자 API 제출을 구분한다.
4. 표 하나 누락·추가·교체, 잘못된 복호화 증명, 화면 결과만 변경을 탐지한다.
5. 서명 확인증을 발급한 뒤 다른 원장을 제시하면 사본 비교로 충돌을 탐지한다. 사본이 없어 탐지 못 하는 경우도 그대로 기록한다.
6. 엔진 커밋 직전/직후 응답 유실, 서명 실패, 중간 작업자 종료, 마감 경합, 백업 복구를 시험한다.
7. OTP 만료·재발송·예산 소진·필수 정책 우회·새 세션/다른 선거 재사용을 모의 발송으로 검사한다.
8. 공개 묶음·오류 로그·전달 URL에서 개인정보/자격/OTP/키 유출을 검사한다. 운영자 자신이 만든 정상 자격의 표가 원형 검증에 통과할 수 있음을 잔여 한계 벡터로 남긴다.

현재 공식 배포 목록은 3.3.0을 제공하고 개발 변경 기록은 추가 암호 수정과 자료 형식 변경을 명시한다. 실험 버전을 고정하고 해당 수정의 영향을 확인한다. 단순히 최신 개발판으로 바꾸거나 낮은 위험 용도라는 이유로 알려진 결함을 무시하지 않는다. AGPL 의무는 실제 소스 수정·기표 JS 제공·서비스 결합·도구 배포 형태로 검토한다. 서비스 분리만으로 의무가 면제되거나 모아이 전체 공개가 자동 확정된다고 단정하지 않는다. [공식 배포](https://www.belenios.net/software.html), [변경 기록](https://raw.githubusercontent.com/glondu/belenios/master/CHANGES.md)

## 11. 실행 경계

이번 요청으로 확정한 것은 계획이다. 실제 설치·서비스 기동·운영 DB 변경·문자 발송·외부 소스/검증 자료 공개·커밋·푸시·배포는 수행하지 않았다. 이전 로컬 영수증 시제품의 테스트나 빌드 결과를 이 계획의 구현·보안 검증 결과로 사용하지 않는다.

이후 검토는 이 신뢰 범위 안의 구현 결함과 증거의 재현성을 중심으로 한다. 독립 발급자·임계 키 보관자·강요 저항이 없다는 이유로 전체 목표를 다시 B-1로 바꾸지 않는다.
