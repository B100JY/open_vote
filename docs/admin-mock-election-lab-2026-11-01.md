# 관리자 모의 선거 테스트실 (2026-11-01)

## 진입과 권한
- 주소: /admin/manage → 모의 선거 테스트실 → /admin/preview/sandbox
- 기존 AdminGate adminOnly 로 총괄 관리자만 접근.
- 코드, 투표 기록, 영수증, 모의 임시 서명키는 브라우저 메모리에서만 보관하며 새로고침 시 초기화.
- 운영 DB/API/SMS/포인트 사용이나 명부 접근이 없으며 DB 마이그레이션도 없음.

## 이용 과정
1. 선거명, 투표 항목, 단일/연기명/항목별 찬반/순위 투표, 기권 허용 여부를 입력해 모의 선거 생성.
2. 임의 코드로 실제 BallotSheet 투표·확인·제출 UI 사용. 한 코드당 한 번씩, 다른 코드로 추가 투표.
3. 실제 VoteCompleteScreen 에서 영수증 확인 및 합성 서명 확인증 파일 저장.
4. 종료 전후 모두 실제 ResultsPage 와 VerifyPage 를 열어 결과·영수증·공개 원장 확인.
5. NativeAuditPanel 의 공개 자료 받기·검증 버튼에서 실제 verifyBundle 함수로 서명·약정·원장·재집계 검사.
6. 모의 종료·다시 진행, 새 모의 선거 만들기로 반복 점검.

## 프로덕션과 격리
- 운영 API/DB의 결과·원장 종료 전 공개 제한은 변경하지 않음.
- 모의 결과 조회 시에만 종료된 스냅샷을 주입하므로 운영 원장과 상태는 불변.
- 투표지, 완료, 결과, 검증, 네이티브 감사 패널의 **실제 운영 컴포넌트**를 재사용하고 데이터 원천만 브라우저 메모리로 변경.
- SHA-256/영수증/원장 해시와 P-256 서명·약정·검증 함수도 실물 사용. 서명은 **모의 브라우저 임시 키**로 생성하며 운영 서명·실제 적격자 인증에 대한 증거가 아님.
- 모의 코드는 실제 문자 인증·유권자 명부·발급 정책을 시험하지 않음. 운영 선거의 비밀투표 보안 테스트로 대체할 수 없음.
- 1000표 제한. 검사 파일 역시 모의 자료이므로 실제 투표 증빙에 사용하면 안 됨.
