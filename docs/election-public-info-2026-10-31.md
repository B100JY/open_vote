# 공개 투표 안내·단체명 분리 (2026-10-31)

- 생성 화면에 단체명(선택, 최대 120자)과 ‘투표 설명을 공개 화면에도 표시’ 옵션을 추가한다. 설명 공개는 기본 꺼짐이다.
- 기존 선거도 `description_public=false`, `organization_name=''`로 시작한다. 기존 제목·설명·서명된 시작 규칙은 변경하지 않는다. 이미 제목에 합쳐 쓴 단체명을 임의로 분해하거나 서명 자료를 다시 쓰지 않는다.
- 단체명은 홈 카드·공개 안내·투표 용지·내 투표 관리에서 제목과 다른 줄·글자 크기로 표시한다. 새로 생성할 때부터 따로 입력한다.
- 투표 안내(`/elections/[id]`)는 설명 공개를 켠 경우에만 설명을 표시한다. 참여자는 문자 링크·코드로 확인한 기표 화면에서 기존처럼 설명을 읽는다. 내용·결과 전체의 열람 제한은 별도로 유지한다.
- 공개 목록·상세·결과 API는 비공개 설명을 서버에서 제거한다. 유효한 참여 확인 또는 소유자·관리자 권한이 있으면 원문을 제공한다. 공개 화면만 본 사람에게 참여 확인 쿠키를 발급하지 않는다.
- 서명된 감사 자료에도 설명 원문이 들어 있으므로 설명 비공개일 때에는 자료 다운로드도 참여 확인·관리 권한을 요구한다. 서명을 깨뜨리는 부분 삭제는 하지 않는다. 기존에 공개된 사본을 소급 회수하는 것은 아니다.
- 시작 규칙·현재 기준점 저장을 카드 우측 상단 `···`의 ‘검증·감시’로 이동했다. 키보드로 열 수 있는 기본 details/summary를 사용한다. 자료를 받을 수 없는 방문자에게는 링크·코드 확인 안내를 보여준다.
- 생성은 기존 `workspace_create_billed` 트랜잭션 안에서 단체명·공개 옵션을 저장한 뒤 감사 설정을 고정한다. 기존 포인트·자격·서명 절차는 재사용한다.

검증: 공개 상세·결과의 설명 제거, 감사 자료의 비인가 접근 차단, 잘못된 선거 쿠키 거부, 참여자 설명 열람을 실제 라우트에 mock DB로 시험한다. 격리 PostgreSQL에서 migration 재적용·기본 비공개·단체명·감사 생성·잘못된 입력 롤백·권한 기준선을 확인한다. 실제 문자 발송 및 운영 테스트 선거 생성은 하지 않는다.
