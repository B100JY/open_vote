# 명부 엑셀 가져오기

`명부·단체문자 → 여러 명 한 번에 가져오기`에 `.xlsx` 파일 가져오기를 추가했다. 기존 이름,전화번호 붙여넣기도 유지한다.

## 사용자 흐름

1. 엑셀 파일 선택(5MB 이하).
2. 시트 선택, 첫 행이 열 이름인지 선택.
3. 전화번호·이름 열 지정, 그룹 열은 선택. 기본 열 이름을 인식해 자동 지정하며 직접 바꿀 수 있다.
4. 미리보기에서 번호·이름·그룹 확인 후 저장. 한 번에 500행까지.

파일은 브라우저에서 읽고, 저장을 누를 때 지정한 연락처와 그룹만 기존 인증 API에 보낸다. 원본 파일과 선택하지 않은 메모 등은 서버로 보내지 않는다. `.xls`는 `.xlsx`로 다시 저장하도록 안내한다. 읽기 라이브러리는 파일 선택 때만 동적으로 로드한다.

## 정규화·저장 규칙

- 숫자 셀로 변환돼 없어진 휴대폰 앞자리 0과 +82 국가번호를 정규화하고 보정 행 수를 표시한다.
- 그룹 셀은 쉼표·세미콜론·파이프·줄바꿈으로 여러 그룹을 지정할 수 있다. 그룹당 60자, 한 행에 20개까지다. 없는 그룹은 현재 계정 아래에 자동 생성한다.
- 위에서 선택한 소속 그룹도 함께 적용한다. 그룹 열을 지정하지 않아도 된다.
- 파일 안의 같은 번호/같은 이름은 그룹 합집합으로 한 명으로 합친다. 같은 번호에 다른 이름이면 행 오류로 처리한다.
- 기존 번호를 가져오면 이름을 갱신하며 기존 그룹은 보존하고 새 그룹만 추가한다. 기존 직접 수정·붙여넣기 규칙은 유지한다.
- 잘못된 행을 조용히 제외하지 않는다. 오류 행과 이유를 보여주며 저장을 막는다. 서버 저장은 단일 트랜잭션으로, 실패 시 새 그룹과 연락처 모두 롤백한다.
- 소유자는 요청의 로그인 계정으로 결정한다. 다른 계정의 그룹 ID는 RPC에서도 거부한다. 실제 유권자 명부나 투표에는 영향을 주지 않는다.

## 구현·검증

- `read-excel-file@9.3.13` 고정, npm audit 취약점 0개. 공식 [사용 규격](https://github.com/catamphetamine/read-excel-file)을 확인했다.
- `supabase migration new contacts_sheet_import`로 생성한 파일은 기존 `20261029030000` 테이블 의존성 뒤에 오도록 `20261029040000_contacts_sheet_import.sql`로 정렬했다. 공유 DB의 `app_open_vote` 함수만 추가했다. PUBLIC/anon/authenticated EXECUTE 철회, service_role만 허용, 권한 기준선 통과.
- 단위 테스트 117개 통과. 열 순서, 헤더 없음, 그룹 선택사항, 숫자 번호, 국가번호, 중복 그룹 합치기, 이름 충돌, 잘못된 행/범위 검증.
- 합성 OpenXML 파일을 실제 라이브러리로 읽어 다중 시트·숫자/문자 셀·중복 그룹·헤더 없는 시트를 확인했다.
- 격리 PostgreSQL에서 마이그레이션 두 번 적용, 반복 가져오기 중복 방지, 기존 그룹 보존, 계정 간 격리, 잘못된 한 행에 대한 전체 롤백 확인. ESLint·Next.js 프로덕션 빌드 통과.
