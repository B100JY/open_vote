# 모아이투표 제품 결정 v0.8 — 일상적인 단체 의사결정용

> **최신 확정 계획:** [v1.0 기존 서비스 기반 경량 감사 계획](voting-native-audit-plan-2026-10-28.md)이 우선한다. Belenios 도입과 운영자 비신뢰 B-1 연구는 보류하고, 기존 모아이에 표준 해시·서명·숨김 약정·공개 집계 재검증을 추가한다. 아래는 과거 검토 기록이며 현재 구현 완료를 뜻하지 않는다.

- 결정일: 2026-10-28
- 근거: 사용자가 고도의 보안·큰 이해관계가 걸린 선거보다, 일상적인 단체 의사결정에 가볍게 쓰는 서비스를 우선한다고 명시했다.
- 상태: 제품 방향·구현 범위 확정. 이 문서가 기능 구현·보안 시험·배포 완료를 의미하지 않는다.
- 우선순위: 이전 원장 확인증 설계 v0.3~v0.7과 B-1 격리 실험 계획보다 이 결정문을 우선한다. 이전 문서는 검토 이력으로 보존한다.

## 1. 확정한 방향

**기존 모아이투표를 유지하면서, 운영자 신뢰를 전제로 접근 제한·개인 확인증·사후 공개 검증을 보강한다.** 매 선거마다 독립 자격 발급자나 집계 키 보관자를 모집하지 않는다. Belenios 도입·임계 암호화·별도 앱 개발은 현재 제품의 선행 조건에서 제외하고 연구를 보류한다.

주요 대상은 동아리·모임·단체의 안건 결정과 일반적인 내부 투표다. 운영자까지 적대자로 보는 보안이나 엄격한 제도적 보증이 필요한 선거의 적합성을 주장하지 않는다. 법적 효력·특정 선거 규정 충족 여부를 제품 설명만으로 보증하지 않는다.

## 2. 지킬 보호와 수용할 한계

| 구분 | 제품 결정 |
|---|---|
| 일반 공개·선거 생성자 | 개별 선택을 명부와 연결해서 볼 수 있는 화면·API·내보내기를 제공하지 않는다. 운영 중에는 참여 현황만 보인다. |
| 데이터 취급 | 명부와 표를 분리하고, 개인 표에 신원·접수 시각·접수 순서를 추가하지 않는다. 요청 본문·인증 비밀·신원과 표의 대응을 로그에 남기지 않는다. |
| 서버·인프라 운영자 | 기표 요청 처리 중 신원과 평문 선택에 접근할 수 있다. 원시 DB·백업·로그의 메타데이터에서도 연결 가능성이 남는다. 이 권한자에게 암호학적으로 비밀이 보장된다고 하지 않는다. |
| 중복 투표 | 1인 1회와 마감 검사를 서버에서 원자적으로 처리하고, 재시도는 같은 접수 결과로 수렴시킨다. |
| 개인 확인 | 참여자가 서버 밖에 보관한 확인증으로 자기 기록의 포함과 보관 기준점의 연결을 확인하게 한다. |
| 전체 검증 | 공개된 표의 집계 재계산·자료 무결성을 검사한다. 모든 공개 표가 실제 적격자의 의사라는 사실까지 수학적으로 증명한다고 하지 않는다. |
| 운영자 부정 | 운영자의 유령 표·악성 웹 코드·선택적 자료 제공을 완전히 차단하지 못한다. 확인증과 독립 사본이 실제로 비교되는 범위에서 사후 이상을 발견할 기회를 높인다. |
| 결과 추론 | 소수 참여·만장일치에서는 결과 자체로 개인 선택이 추정될 수 있다. 생성 시 안내한다. |

관리 화면을 보지 못하게 하는 것과 원시 DB 권한자를 막는 것은 다르다. 접근 제한·로그 최소화는 계속 지킬 의무이며, 운영자 신뢰를 택했다고 개인정보 연결 필드를 새로 만들지 않는다.

## 3. 원장과 확인증: 경량 보강으로 진행

해시 체인과 서버 서명 확인증이라는 최초 취지는 유지한다. 다만 **접수 순서와 공개 평문 표를 맞춰볼 수 있는 연결값은 공개하지 않는다.** 순서를 숨기던 현행 구조를 체인 때문에 되돌리지 않는다.

이전 검토의 숨김 약정 방식을 경량 보강의 기준으로 삼는다. 참여자 브라우저가 보관하는 비밀값으로 자기 약정을 확인하고, 서버 서명은 해당 기준점을 발급한 사실을 증언한다. 실제 정규 직렬화·서명키 보관·접수 트랜잭션·확인증 형식은 구현 명세와 테스트에서 고정한다. 새 암호 알고리즘이나 자체 영지식 증명은 개발하지 않는다.

최종 공개본에는 선거 규칙, 표 수, 공개 원장·집계 결과, 체인과 최종 기준점을 함께 고정한다. 개인 확인은 자기 표의 공개 목록 포함과 자기 약정의 체인 포함을 각각 확인한다. **숨김 약정 집합과 평문 표 집합 전체의 일대일 대응은 보편 증명이 아니다.** 본인이 확인하지 않은 표의 변경이나 부정 추가를 모두 잡는다고 하지 않는다.

참여자는 확인증 파일을 내려받아 독립 보관할 수 있다. 화면은 ‘확인증 저장’과 ‘내 표 확인’ 중심으로 단순하게 만들고 복잡한 해시는 상세에서만 보여준다. 짧은 표시 코드를 원본 확인증의 복구 키나 강한 인증 수단으로 쓰지 않는다. 서버에 신원과 확인증을 연결하는 분실 복구 기능을 새로 만들지 않는다.

시작 규칙·서명 공개키와 최종 검증 묶음은 내려받아 주최자·참여자가 따로 보관할 수 있게 한다. 독립 감시 서비스를 의무 운영하지 않는다. 외부 사본이 없거나 실제 비교가 없으면 전체 재작성·분기 탐지 보장이 제한된다는 점을 그대로 인정한다. 최초 자료를 서버에서만 받았다면 독립 확인 완료로 표시하지 않는다.

## 4. 선택형 기표 직전 문자 인증

생성자가 **‘제출 전 휴대폰 문자 인증’**을 선택할 수 있게 한다. 기본값은 해제다. 켜면 명부에 등록된 번호로 새 인증을 마친 뒤 제출한다. 끄더라도 기존 링크/코드 자격과 1회 투표 검사는 유지한다.

설정 안내는 다음 수준으로 간단히 쓴다.

> 링크나 투표 코드가 다른 사람에게 넘어갔을 때 무단 제출 위험을 줄입니다. 등록된 휴대폰으로 문자 인증을 해야 하며, 추가 문자 비용이 발생합니다.

상세 안내와 검증 보고서에는 문자 인증이 운영자 부정을 막는 암호학적 자격 증명이 아니며 공개 원장만으로 이행 여부를 확인할 수 없다고 쓴다. 선언문에 설정을 고정하되 검증 상태는 `PRECAST_AUTH_DECLARED`로 표시하고 ‘OTP 수행 검증 완료’로 표시하지 않는다. 휴대폰을 보지 못하는 공격자에 대한 추가 방어이며 피싱·단말 탈취·문자 가로채기를 완전히 막는다는 표현은 쓰지 않는다.

구현 범위:

- 기존 모아이 접수 경로에서 선거·유권자 세션에 결합된 짧은 1회 승인을 검사한다. 별도 Belenios 프록시나 블라인드 티켓을 도입하지 않는다. 기표문 digest와 신원을 결합하는 새 인증 저장소도 만들지 않는다.
- 공개·외부 연동·관리자·재시도 경로까지 동일한 필수 정책을 적용한다. 설정 누락으로 우회되면 출시 차단 항목이다. 서버 운영자가 코드를 바꾸는 공격을 이 검사로 막는다고 하지는 않는다.
- 승인 후 아직 접수되지 않은 요청은 유효기간과 마감 안에서 안전하게 재시도할 수 있게 한다. 확정 여부가 불명확하면 조회·조정 후 처리하고 승인을 먼저 소모해 표를 잃게 만들지 않는다. 확정된 같은 기록의 공개 증거 조회에는 새 문자를 요구하지 않는다.
- 명부 번호로만 발송하며 화면은 ‘등록된 연락처로 발송합니다’로 안내한다. 번호 임의 입력·기표 중 변경은 제공하지 않는다. 번호 정정이 필요한 선거는 시작 전에 처리하고, 개시 후 관리자 임의 예외 통로를 만들지 않는다.
- 재발송 대기·시도 제한·선거별 발송 예산 상한·중복 과금 방지를 둔다. CAPTCHA·PoW·외부 인증 서비스는 필수 의존성으로 추가하지 않고 남용 관측 후 판단한다. 번호만 아는 비인증 요청으로 발송하지 않는다.
- 문자 본문에는 코드와 최소 안내만 넣고 민감한 선거 이름은 기본 생략한다. 인증번호·토큰·선택·전화번호 원문을 로그와 오류 추적에 넣지 않는다.
- 마감은 사전에 정한 시각으로 유지한다. SMS 지연에 따른 자동 유예나 마감 후 표 추가는 도입하지 않는다. 생성자와 참여자에게 수신 지연·실패 위험과 미리 인증할 필요를 안내한다.
- 휴대폰 미보유자나 등록 번호를 쓰지 못하는 사람은 이 설정에서 제출할 수 있음을 보장하지 않는다. 생성자가 시작 전에 명부와 참여 가능 여부를 확인하게 한다. 발송 실패 시 자동으로 인증을 생략하지 않는다.

문자 인증은 가벼운 추가 방어다. 이 기능 때문에 모든 선거에 새 앱·Passkey·독립 자격 전달을 의무화하지 않는다.

## 5. 사용자에게 할 약속

기본 설명:

> 단체의 의견을 간편하게 모으고, 투표가 끝난 뒤 내 기록과 결과를 확인할 수 있습니다.

이용 안내의 보안 상세:

> 일반 이용자와 투표 관리 화면에는 개인의 선택이 공개되지 않습니다. 서비스 운영자의 시스템 접근까지 암호학적으로 차단하는 방식은 아닙니다. 확인증으로 자기 기록을 확인할 수 있지만, 모든 부정을 자동으로 찾아내는 것은 아닙니다.

‘아무도 선택을 알 수 없다’, ‘시간·순서 추적이 불가능하다’, ‘조작 불가능’, ‘블록체인으로 모든 부정 방지’ 같은 절대 표현은 쓰지 않는다. 영수증이 선택을 증명하는 형태이면 타인에게 공유하지 말라고 알린다. 짧은 첫 화면에 기술 경고를 나열하지 않고 이용 안내의 상세와 생성 시 관련 설정 옆에 필요한 범위를 안내한다.

## 6. 실행 순서와 완료 기준

1. 현재 구현·시제품과 위 결정의 차이를 점검한다. 현행 UI의 과도한 보장 문구를 바로잡고 개인정보 노출·미마감 결과 공개를 막는 기존 규칙을 유지한다.
2. 경량 체인·서명 확인증의 구현 명세를 정하고 합성 자료로 시험한다. 공개 자료만으로 접수 순서와 선택을 복원하는 공격, 기록 삭제/변경, 서명·키 변경, 공개본 분기를 검사한다. 탐지하지 못하는 경우도 보고한다.
3. 선택형 문자 인증을 모의 발송으로 검증한다. 누락·우회·재시도·동시 요청·마감·발송 예산·인증 로그 유출을 검사한다. 실제 문자 수신·제공자 로그·과금 검증은 별도 확인 대상으로 남긴다.
4. 실제 보장 범위와 맞는 안내·확인 화면을 만든다. 필요한 코드 검사와 검증을 마친 뒤 별도 배포 절차를 따른다.

이후 검토는 확정한 위협 모델 안에서 구현 결함을 찾는 데 집중한다. 운영자 비신뢰 암호화·독립 보관자·강요 저항을 갖추지 않았다는 이유만으로 현재 제품을 계속 재설계하지 않는다. 중복 기표, 개인정보의 불필요한 공개, 접수 유실, 서명 검증 오류와 같은 실제 결함은 제품 용도가 가볍더라도 해결해야 한다.
