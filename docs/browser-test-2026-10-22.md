# 다모음 대의원 선거 전 브라우저 점검 — 2026-10-22

## 결론

연기명 선거의 생성·중복 명부 정리·정원 제한·참여율·일시중단/재개·자동 마감·최종 집계·공개 원장 검증을 확인했다. 시험 결과는 총 2표, 유효표 1표, 기권 1표이며 가후보 1표·나후보 0표·다후보 1표로 예상과 일치했다. 실제 문자 수신과 대규모 동시 투표를 검증한 결과는 아니다.

선거 전 보완할 화면/안내 문제 3건을 확인했다. 제품 코드는 수정하지 않았다.

## 발견 사항

### B-01 [P2] 미투표 상태에서도 완료 화면이 성공으로 표시됨

- 재현: 투표 이력이 없는 새 탭에서 `/vote/complete`에 직접 접속한다.
- 실제: 영수증이 없는데도 초록색 완료 아이콘과 “투표가 완료되었습니다”가 표시된다. 영수증을 복사하라는 안내도 그대로 나온다.
- 영향: 완료 주소를 잘못 열거나 공유받은 유권자가 실제로 투표했다고 오해할 수 있다. 이 현상으로 표가 생성되지는 않는다.
- 원인 확인: `src/app/vote/complete/page.tsx:49`의 완료 제목은 영수증 존재 여부와 관계없이 출력된다.
- 제안: 영수증이 없을 때는 완료 여부를 이 화면에서 확인할 수 없다고 안내하고 개인 링크로 확인하도록 유도한다. 실제 투표 여부를 단정하지 않는다.
- 증거: [미투표 완료 화면](browser-test-2026-10-22/01-complete-without-vote.jpg).

### B-02 [P2] ‘영수증 복사’ 출력 전체를 검증창에 붙이면 정상 영수증도 못 찾음

- 완료 화면의 복사 코드는 `election_id=…`, `receipt_hash=…`, `salt=…` 세 줄을 만든다(`src/app/vote/complete/page.tsx:34`).
- 재현: 시험 기권표의 실제 영수증 해시로 검색하면 찾는다. 같은 해시를 위 세 줄 형식에 넣어 검색창에 붙이면 찾지 못한다. Salt는 이 재현에서 시험용 문자열을 사용했다. 실제 완료 화면 복사 버튼 클릭 자체는 도구 제약으로 검증하지 못했다.
- 실제: “공개 원장에서 이 영수증 해시를 찾지 못했습니다.”가 표시된다.
- 원인 확인: `src/lib/verification.ts:70`은 공백 정리·소문자화·`0x` 제거만 하며 `receipt_hash=` 값을 추출하지 않는다. 한 줄 입력창은 붙인 줄바꿈도 제거한다.
- 영향: 안내대로 영수증을 보관한 사람이 정상 접수된 표를 누락으로 오해할 수 있다.
- 제안: 전체 복사 형식에서 `receipt_hash`를 파싱하거나, 해시만 복사하는 별도 버튼을 제공한다. 형식 오류와 실제 영수증 미발견을 구분한다.
- 증거: [해시 단독 검색 성공](browser-test-2026-10-22/05-ledger-verified.jpg), [복사 형식 검색 실패](browser-test-2026-10-22/06-copied-receipt-not-found.jpg).

### B-03 [P2] 보안 설명이 영수증 공유 시 드러나는 정보를 잘못 안내함

- `/trust`에는 영수증 번호가 암호화되어 타인이 투표 내용을 알 수 없다는 설명이 있다(`src/app/trust/page.tsx:125`).
- 실제 종료 원장은 영수증 해시와 선택 내용을 함께 공개한다. 브라우저에서 시험 영수증을 검색하면 “기권”이라는 선택까지 표시된다.
- 신원과 투표지를 잇는 DB 연결이 발견됐다는 의미는 아니다. 다만 본인이 영수증을 타인에게 보내면 그 타인이 원장에서 선택 내용을 확인할 수 있다.
- 제안: 암호화와 해시를 구분하고, 영수증을 공유하면 선택 내용도 드러날 수 있음을 정확히 안내한다.
- 증거: [종료 원장과 영수증 검색](browser-test-2026-10-22/05-ledger-verified.jpg).

## 보조 검증과 한계

- `npm test`: **68/68 통과**. 선택 정규화·기권·영수증/원장 검증·공유 Auth 가드·과금·명부 처리 포함. 실제 브라우저/운영 RPC 통과와는 구분한다.
- `npx eslint src`: 통과.
- `npm run lint`: 실패. 기본 `eslint`가 `.claude/worktrees` 안의 다른 체크아웃과 생성된 `.next`까지 검사하여 1,193 errors / 11,453 warnings. 이 수치를 현재 앱 소스 결함 개수로 해석하면 안 된다.
- 빌드·배포·코드 수정·커밋·푸시·스키마 변경은 하지 않았다. 기존 미커밋 파일을 변경하지 않았다.
- 날짜 입력의 자동 `fill`이 실제 React 상태에 반영됐는지 확정하지 못했다. 잘못된 시작/마감 순서에 대한 **브라우저 폼 검증은 미확인**이다. 시각 조건의 투표 차단·자동 마감은 별도의 시험 DB 시각 설정으로 확인했다.
- 브라우저 기본 확인창 승인에 도구 오류가 있었으며 이 자체를 제품 결함으로 분류하지 않았다. 실제 Chrome 투표 최종 승인, 확인 취소 후 재선택, 성공 직후 영수증 복사/새로고침은 수동 재확인이 필요하다.
- 실제 SMS·재발송 토큰 회전·부분 발송 실패·실제 휴대폰 수신·문자 앱 내부 브라우저·iOS Safari·Android Chrome은 미검증이다.
- 메일 매직링크·회원가입/초대/승인·역할이 다른 생성자의 교차 접근·포인트 부족 실제 생성·동시 제출 경쟁·대량 명부/부하·장시간 폴링·네트워크 단절 후 복구는 미검증이다.
- 일반표와 기권 합계 2표의 소규모 시험이며 실제 대의원 선거 정원·동률·당선 기준을 조합 규정에 맞게 판정하는 검증은 별도로 필요하다. 앱 결과 화면도 판정은 조합 규정을 따르도록 안내한다.

## 시험 데이터 정리

- 해당 시험 선거 UUID로 범위를 제한해 삭제했다. FK cascade로 시험 명부 4행과 투표지 2행을 삭제했다.
- `adjust_credits(..., 40, 'refund', ...)`로 차감분 전액을 환불했다. 다른 거래를 덮어쓰는 방식으로 잔액을 초기화하지 않았다.
- 차감/환불 거래와 시험 생성·상태 변경·정리 감사 기록은 추적을 위해 보존했다.
- 시험 선거·명부·표가 모두 0건인 것을 DB 조회로 검증했다. 시험 링크는 유효하지 않게 됐다. 실제 회원·다른 앱 데이터·공유 Auth는 변경하지 않았다.
- 임시 로컬 링크 서버를 종료했다. 가상 명부 CSV와 화면 증거는 아래 폴더에 보존했다.
