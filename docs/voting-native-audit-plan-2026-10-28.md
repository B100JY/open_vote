- 대상: 일상적인 모임·단체의 의사결정. 운영자를 일정 부분 신뢰하는 서비스다.
- 상태: 계획 작성만 완료. 구현·보안 시험·운영 DB 변경·실제 문자 발송·배포 완료가 아니다.

## 1. 목표와 제외 범위

목표는 **운영자가 규칙·접수 승인·기록·결과의 일치를 자료로 설명하고, 주최자·참여자가 그 자료를 다시 검사할 수 있게 하는 것**이다. ‘부정이 전혀 없었음’ 또는 ‘운영자도 선택을 알 수 없음’을 증명하지 않는다.

기존 회원·명부·과금·문자 링크/코드·기표·마감·투표 방식은 유지한다. 새 외부 투표 엔진·독립 자격 발급자·복수 키 보관자를 요구하지 않는다. 동형 암호·영지식 증명·믹스넷·익명 자격을 직접 개발하지 않는다. 해시·난수·전자서명은 표준 API/라이브러리를 사용하며, 감사 자료 형식과 상태 처리를 직접 구현한다.

| 항목 | 제공하는 확인 | 제공하지 않는 보장 |
|---|---|---|
| 시작 규칙 | 보관한 최초 규칙과 현재 자료의 일치 | 독립 최초 사본이 없을 때 전체 규칙 재작성의 탐지 |
| 접수 확인증 | 서버가 해당 약정을 특정 원장 기준점에 포함했다고 서명한 사실 | 실제 유권자 의사·악성 웹 코드 부재 |
| 내 표 | 로컬 영수증과 공개 표의 일치, 내 약정의 이력 포함 | 확인하지 않은 모든 사람의 표가 올바른지 |
| 이력 | 저장한 기준점과 최종 체인의 연결 | 실제 비교하지 않은 분기·기준점 이후 모든 변경의 자동 탐지 |
| 집계 | 공개된 표의 규칙 검사와 결과 재계산 | 공개 표가 모두 실제 적격자가 제출한 표인지 |
| 중복 | 공개 영수증/약정의 중복 검사와 서버 1회 소비 처리 | 공개 자료만으로 독립적인 1인 1표 증명 |
| 문자 인증 | 정책 선언과 접수 경로의 강제 여부 시험 | 운영자 OTP 우회 부재의 수학적 증명 |

서버는 기표 시 신원 토큰과 평문 선택을 처리한다. 원시 DB·백업·런타임 권한자는 메타데이터로 연결하거나 내용을 읽을 수 있다. 일반 관리자 화면·API의 접근 제한과 로그 최소화는 계속 지키되, 운영자 대상 암호학적 비밀성을 주장하지 않는다. 소규모 결과·희귀한 선택 조합·영수증 공유로 인한 추론도 남는다.

## 2. 현재 기반과 추가 작업

현재 [영수증/원장 해시](../src/lib/verification.ts), [로컬 감사 시제품](../src/lib/receipt-audit.ts), [기표 API](../src/app/api/vote/link/route.ts)를 기반으로 한다. 시제품은 자기 표·규칙·마감 기준값 대조를 제공하지만 서버 서명·접수 체인·완전한 독립 집계 검증까지 완성된 것은 아니다. 이전 테스트/빌드 결과를 신규 기능의 검증 결과로 재사용하지 않는다.

```text
기존 접수: 유권자 확인 → 선택 규칙·기간 검사 → 1회 투표 확정
추가 감사: 시작 규칙 고정 → 약정 이벤트 → 서명 확인증 → 최종 묶음
별도 검사: 저장한 확인증/기준점 + 공개 묶음 → 로컬 검증 보고서
```

기표 성공의 원본은 기존 투표 저장소 하나로 유지한다. 별도 엔진·별도 결과 DB를 만들지 않는다. 서명 생성·자료 생성의 실패는 재시도로 복구하되 새로운 표나 새로운 과금이 발생하지 않게 한다.

## 3. 규칙·키·자료 형식 고정

개시 전에 다음을 규칙 고정본에 넣고 서명한다: 선거 ID, 후보 ID·이름·순서, 투표 방식·선택 수·기권·순위 점수/동률 규칙, 정원, 개시·마감, 1회 투표 정책, 문자 인증 여부, 참여 상태의 관리자 열람 범위, 공표 기한, 감사 형식 버전, 서명 알고리즘·공개키와 키 ID.

명부의 이름·전화번호·그 단순 해시 목록은 공개 고정본에 넣지 않는다. 명부 진위와 정원은 주최자 확인·운영 절차로 남긴다. 최초 공개키를 현재 서버가 준 새 키로 자동 교체하지 않는다. 주최자·참여자가 시작 고정본을 독립 저장할 수 있게 한다. 독립 저장본을 직접 비교하지 않았으면 `MANIFEST_ANCHOR_UNCONFIRMED`로 표시한다.

기술 기준은 SHA-256과 암호학적 난수, 표준 전자서명이다. 초기 서명 후보는 Web Crypto/Node 표준 API로 처리할 수 있는 ECDSA P-256/SHA-256으로 두고 P0에서 지원 환경·서명 바이트 형식·공개키 인코딩을 고정한다. 암호 원시 연산을 직접 구현하지 않는다. JSON 정규화는 검토된 JCS 구현 등 결정적 형식을 사용한다. 숫자 범위·문자열·배열 순서·알 수 없는 필드의 처리와 용도별 도메인 구분을 문서·테스트 벡터로 고정한다. [Web Crypto](https://www.w3.org/TR/2017/REC-WebCryptoAPI-20170126/), [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)

서명 개인키는 공개 원장·DB 덤프·검증 묶음과 분리해 보관한다. 공개키는 선거 시작에 고정하고 도중 교체를 정상 처리하지 않는다. 유실·침해 때는 조용히 새 키로 재서명하지 않고 해당 증거의 상태를 표시한다. 백업과 복구·권한을 시험한다. 키 분리가 운영자 자신을 차단하거나 마감 전 열람을 방지한다는 뜻은 아니다.

## 4. 접수 순서를 선택과 연결하지 않는 체인

기존 공개 평문 표는 영수증 해시순으로 제공한다. **접수순 이벤트에는 선택·선택 digest·공개 영수증 해시·신원·정확한 접수 시각을 넣지 않는다.** 공개 표와 결정적으로 맞춰볼 수 있는 값도 넣지 않는다. ballots에 시각·순번·명부 ID를 추가하거나 명부의 투표 시각을 기록하지 않는다.

각 클라이언트는 현재 영수증의 salt와 별도로 충분한 난수 비밀값 k를 생성하고, 다음 논리의 숨김 약정 c를 만든다.

```text
c = SHA256(정규화(용도, 선거ID, 규칙해시, 영수증해시, k))
vote_event = (형식, 선거ID, 규칙해시, 인덱스, 종류, c)
head = SHA256(정규화(체인용도, previous_head, vote_event))
```

이는 검토용 구조이며 바이트 명세·예외 처리·정규화는 P0에서 확정한다. k와 salt는 원장에 공개하거나 서버의 분실 복구 저장소에 넣지 않는다. 서버는 기표 요청을 처리하며 c와 표의 관계를 알 수 있으므로 운영자 비신뢰 익명성이 아니다. 명시적 신원-확인증 조회 표는 새로 만들지 않는다.

개인 확인 때는 ① 로컬 k로 계산한 c의 체인 포함, ② 로컬 salt로 대조한 자기 표의 공개 목록 포함을 각각 확인한다. **약정 집합과 공개 평문 표 집합 전체의 일대일 대응은 공개 증명하지 못한다.** 표 수 일치만으로 그 대응이나 유령 표 부재를 주장하지 않는다. 숨김 약정의 opening(k 등)을 개인 확인 편의를 위해 중앙 수집하지 않는다.

빈 이벤트를 정기 생성하거나 머클 구조를 초기 필수 기능으로 추가하지 않는다. 매 표의 약정 이벤트와 시작/마감 이벤트로 연결하고, 공개 체크포인트는 필요할 때 같은 head를 서명·보관한다. 정기 보관의 간격은 부하 측정 후 정하며 공증 시각이라고 부르지 않는다.

## 5. 접수 확인증과 재조회

기표권 소비·표 저장·약정 이벤트·head를 하나의 확정 경계에서 처리한다. 이후 서명은 확정된 이벤트만 대상으로 한다. 완료 서명을 미커밋 자료에 먼저 발급하지 않는다. 서명 실패 때는 ‘투표 접수 완료·확인증 준비 중’으로 나누어 보여준다.

서명하는 공개 페이로드에는 선거/규칙 식별값, c, 이벤트와 previous_head, index·head, 키 ID·형식을 포함한다. 브라우저는 자신의 c와 이벤트·head·서명을 즉시 검사한다. 영수증 해시나 선택은 이 공개 서명 페이로드에 넣지 않는다. 모든 확인증을 공개 조회해도 접수 순서와 공개 표가 바로 이어지지 않아야 한다.

다운로드하는 **개인 확인증**은 공개 서명 자료와 로컬 영수증 해시·salt·k·규칙 고정본을 결합한 파일이다. 타인에게 전달하면 자기 선택을 증명하는 데 쓰일 수 있으므로 개인 보관을 안내한다. 화면은 ‘확인증 저장’, ‘내 표 확인’ 중심이며 긴 해시는 상세로 둔다. 짧은 표시 코드는 원본 복구 키나 소유 증명이 아니다.

재조회 규칙:

- 공개 c/이벤트 ID로 이미 확정된 이벤트·서명만 익명 재조회한다. c는 공개값이며 소유 증명으로 쓰지 않는다.
- 로컬 파일·브라우저에 k와 salt를 보관한 사용자는 공개 서명 자료를 다시 받아 개인 파일을 완성한다. 모든 로컬 비밀을 잃으면 서버가 복구해 주지 않는다.
- 본인 문자 인증만으로 ‘내 영수증’을 찾는 연결 저장소는 추가하지 않는다. 자기 투표권 사용 여부 조회와 개인 확인증 복구를 구분한다.
- 동일 요청 재전송에서 새 표를 만들지 않고 확정 상태를 확인한다. 타인의 공개 c를 넣는 공격, 같은 c에 다른 내용 제출, 토큰 소비 후 응답 유실, 미접수 상태를 구분하는 규격과 시험을 P1에서 완성한다.
- 이미 쓰인 토큰과 공개 c가 함께 왔다는 이유로 두 값이 같은 투표에 속한다고 주장하지 않는다. 공개 이벤트 조회 성공은 새 투표 접수 성공과 다른 응답이다.

## 6. 마감·공개 묶음·집계 검증

마감과 마지막 기표는 같은 선거 경계에서 직렬화해 마감 이벤트 뒤의 표 추가를 거부한다. 마감 시 표 목록의 정렬된 digest, 약정 집합 digest, 표 수, 규칙 해시·최종 head·결과 자료 digest를 함께 고정하고 서명한다. 마감된 선거를 다시 열거나 같은 선거의 다른 최종본으로 덮어쓰지 않는다.

공개 묶음은 시작 고정본, 공개키, 약정 이벤트·서명, 영수증 해시순 익명 표, 결과, 최종 서명 자료, 파일 목록/digest, 검증기 버전·실행 방법으로 구성한다. 이름·전화번호·신원 토큰·IP·salt·k는 넣지 않는다. 상세 선택과 표 목록은 마감 후에만 공개하며 실시간 이벤트 조회에도 선택 단서가 없어야 한다.

독립 실행 검증기는 서버 집계 함수를 호출하지 않고 공개 표에서 선택 규칙을 검사하고 결과를 계산한다. 단일·다중·항목별 찬반·기권·보다식의 실제 canonical 규칙을 명세로 고정한다. 현재 rank는 IRV/STV가 아닌 보다식임을 유지하고 점수·1순위 수·순위별 수·동률 표시를 테스트한다. 검증기 구현이 준비된 방식만 신규 감사 보장을 표시하며 기존 기능을 무조건 삭제하지 않는다.

공개 영수증 중복, 약정 중복, 체인 vote 수와 공개 표 수, 발표 결과와 재계산 결과를 비교한다. 명부 소비 수와의 대조는 **서버 제공 운영 집계**로 별도 표시한다. 한 사람이 다른 자격으로 여러 표를 넣지 않았다는 독립 증명으로 해석하지 않는다.

## 7. 외부 보관과 실패 보고

주최자는 시작 고정본·공개키를, 참여자는 자기 확인증을, 누구나 최종 공개 묶음을 내려받아 보관할 수 있다. 선거 도중 주최자가 공개 기준점을 별도 보관하는 기능도 제공한다. 자동 내부 백업은 장애 복구용이며 독립 사본으로 계산하지 않는다. 외부 미러·추가 서버를 초기 필수로 요구하지 않는다.

서버 밖에서 보관한 자료와 실제로 비교한 항목만 ‘외부 비교 확인’으로 표시한다. 다운로드 기능을 제공했거나 운영자가 자기 파일을 다시 검사한 것만으로 독립 확인 완료라고 하지 않는다. 비교되지 않은 분기·전체 재작성은 남는 위험이다.

보고서 항목은 `PASS / FAIL / UNCONFIRMED / NOT_APPLICABLE`로 구분한다. 최소 검사는 규칙/키 일치, 서명, 개인 표 포함, 약정 체인 연결, 공개 표 규칙·중복, 결과 재계산, 외부 사본 비교다. 개인 확인증을 제공하지 않은 표를 ‘개인 검증 완료’로 집계하지 않는다.

유효한 서명 자료가 고정된 최종 이력과 양립하지 않으면 `SIGNED_HISTORY_CONFLICT`로 근거 파일을 생성한다. 단순 파일 손상·서명 불일치·자료 다운로드 실패와 구분한다. `PROOF_UNAVAILABLE`, `PUBLICATION_OVERDUE`, `MANIFEST_ANCHOR_UNCONFIRMED`도 별도 표시한다. 서명 충돌은 발급 자료 간 모순의 증거이며 고의 부정의 원인을 자동 확정하는 판정은 아니다.

사용자 기본 문구는 **‘공개된 투표 기록과 결과의 일치를 확인할 수 있습니다’**로 한다. ‘조작 불가능’, ‘누구도 선택을 알 수 없음’, ‘모든 부정 부재 증명’이라고 쓰지 않는다. 보안 한계는 이용 안내의 펼침 상세에 설명한다.

## 8. 선택형 문자 인증·참여 상태·IP

생성자가 ‘제출 전 휴대폰 문자 인증’을 선택하며 기본값은 해제다. 기존 자격·마감·1회 소비 검사는 항상 유지한다. 필수 선거에서는 기존 모아이 접수 경로가 선거·유권자 세션에 결합된 짧은 1회 승인을 검사한다. 새로운 외부 엔진 프록시나 암호문 digest-전화번호 저장소를 만들지 않는다.

일반 링크/코드·관리자·외부 연동·재시도 등 모든 제출 경로의 우회를 검사한다. 승인 발급 뒤 미접수 요청은 유효기간·마감 안에서 안전하게 재시도할 수 있게 하고, 이미 확정된 공개 증거 조회에는 재인증·문자 재발송을 요구하지 않는다. 정확한 소비·재시도 상태는 접수 원자성과 함께 검증한다.

명부 번호로만 발송하고 화면은 ‘등록된 연락처’로 안내한다. 번호 임의 입력·개시 후 관리자 개별 예외·발송 실패 시 자동 생략을 제공하지 않는다. 재발송 대기·누적 실패 제한·선거 예산·중복 과금 방지를 두고 문자에는 코드와 최소 안내만 넣는다. 민감한 선거 제목을 기본 생략한다. 수신 지연을 이유로 마감이 자동 연장되지 않으며 시작 전 참여 가능 여부를 확인하도록 안내한다. 실제 발송은 모의 시험과 분리한다.

문자 인증은 링크·코드 유출 위험을 줄이는 추가 방어다. `PRECAST_AUTH_DECLARED`는 정책 선언이며 전원 실제 이행의 공개 증명이 아니다. 운영자는 우회할 수 있고 문자 피싱·단말 탈취 위험도 남는다.

본인의 참여 여부는 유효한 개인 자격/인증 세션으로만 조회하고 전화번호만 입력해서 조회하지 못하게 한다. 속도 제한·다른 선거/사용자 조회 거부·일관된 오류 처리를 둔다. 생성자의 명부 관리상 참여 상태는 권한 있는 기존 범위로 제한하고 개인 선택·체인 위치·시각은 함께 제공하지 않는다. 미참여자의 도용 신고는 조사 단서이지 자동 부정 확정이 아니다.

IP를 표·확인증·공개 원장에 넣지 않는다. 남용 방어용 접속 정보는 목적·기간·권한을 최소화하고 표와 연결하는 새 기록을 만들지 않는다. 앱·프록시·발송 제공자·분석/오류 도구·백업의 토큰/선택/전화번호 로그 유출을 점검한다. 이는 원시 DB 메타데이터·실시간 요청을 보는 운영자를 배제하는 장치는 아니다.

## 9. 구현 단계와 완료 기준

| 단계 | 작업 | 통과 조건 |
|---|---|---|
| P0 명세 고정 | 자료 형식·서명·키/규칙 앵커·집계 규칙·지원 환경 확정 | 표준 테스트 벡터와 공개 예제, 보장/한계 구분, 형식 버전 호환 규칙 확보 |
| P1 접수·체인 | 단일 확정 경계·1회 소비·약정 이벤트·마감·재시도 | 동시 요청·변형 재시도·응답 유실에도 중복/영구 유실 없음, 공개 자료 순서 대입 공격 실패 |
| P2 서명·파일 | 확정 자료만 서명·즉시 검증·개인 저장·공개 재조회 | 미커밋 서명 미발급, 키/이벤트 변조 거부, 서명 장애 후 동일 증거 복구 |
| P3 독립 검증 | 방식별 규칙/집계·최종 묶음·보고서·외부 사본 비교 | 서버 없이 묶음 재검증, 집계와 독립 검증의 고정 벡터 결과 일치, 미확인 표시 정확 |
| P4 문자·제품 | 모의 OTP·필수 경로·예산·참여 조회·쉬운 안내 | OTP 우회·조회 열거·추가 과금/접수 유실 없음, 보안 설명과 실제 검사 일치 |
| P5 운영 준비 | 키/자료 복구·로그/권한·기존 영수증 호환·모바일 성능 | 백업/재시작·복구 검증, 기존 선거 유지, 측정 전 고정한 UX 목표 충족 후 별도 배포 절차 |

필수 시험 벡터:

1. 후보·규칙·서명키 바꿔치기, 다른 선거 확인증, 잘못된 형식·정규화·서명을 거부한다.
2. 공개 체인과 공개 표만으로 접수순 선택을 매핑하는 공격을 시도한다. k·opening·개인 확인증이 공개 묶음에 없는지 검사한다.
3. 내 표 변경/누락, 약정 제거, 과거 이벤트 변경, 최종 표/결과만 변경을 각각 시험한다. 개인 확인과 전체 재계산이 잡는 범위를 구분한다.
4. 동일 표 재시도, 다른 선택으로 같은 식별값 제출, 남의 공개 c 사용, 소비 후 응답 유실, 마감 동시 요청을 시험한다.
5. 투표 커밋 전후·서명 전후·공개 묶음 생성 중 장애를 주입하고 같은 확정 상태로 복구한다.
6. 상충하는 서명 이력·잘못된 서명·미공개·통신 장애의 결과를 구분한다. 독립 사본이 없어 탐지하지 못하는 경우도 기록한다.
7. 방식별 최소/최대·기권·잘못된 후보·중복·순위·동률을 서버 집계와 별도 검증기로 비교한다.
8. 필수 OTP 누락·만료·다른 선거/유권자 재사용·재발송·발송 예산 소진·참여 상태 무차별 조회를 모의 시험한다.
9. 정상 형식 유령 표, 확인하지 않는 사람의 표 변경, 운영자의 실시간 선택 열람을 완전히 막지 못한다는 한계를 보고서와 대조한다.

새 테스트는 이 핵심 불변식과 공격 경로를 검증한다. 단순 ‘테스트 개수’나 화면 정상 표시를 안전성 근거로 쓰지 않는다. 검증 도구를 같은 소스의 다른 UI에서 호출한 것을 독립 구현 교차 검증이라 부르지 않는다. 집계 검증은 명세와 별도 구현으로 비교하고 가능하면 제3자가 공개 벡터로 재현하게 한다.

## 10. 실행 경계와 이후 검토

이번 요청은 계획 재작성이다. 코드·DB·운영 설정·서비스 기동·실제 문자·커밋·푸시·공개 저장소 전환·배포는 수행하지 않는다. 구현 시에는 기존 프로젝트의 권한 기준선·과금 단일 트랜잭션·공유 인증 보호·마이그레이션 절차를 따른다. 운영 적용은 별도 절차로 진행한다.

후속 검토는 이 신뢰 범위의 개인정보 연결·접수 원자성·서명/직렬화·자료 재현성·외부 비교를 중심으로 한다. Belenios의 암호화 집계 증명을 제공하지 않는 점을 기능 한계로 명시하되, 그것을 재도입의 필수 조건으로 삼아 목표를 다시 확대하지 않는다.
