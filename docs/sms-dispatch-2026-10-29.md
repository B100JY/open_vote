# 문자 인증 활성화·간편 SMS·발송 시점 과금

## 사용자 결정

- 추가 문자 인증을 운영에서 활성화한다. 생성자가 새 감사 선거에서 선택하며 기존 선거의 고정 정책은 바꾸지 않는다.
- 안내/일괄 재발송/개별 재발송에서 기존 안내와 간편 SMS를 선택하고 가격을 표시한다.
- 후속 결정: 투표 생성은 무료이며 예상 비용만 안내한다. 발송 직전에 잔액을 확인하고 부족하면 충전을 안내한다.
- 실제 시험 문자 발송·커밋·푸시·머지는 하지 않는다.

## 요율·형식

- 기존 긴 안내: 30P/건 (`VOTE_CREDIT_PER_VOTER`, 기존 이름 호환).
- 간편 SMS: 10P/건 (`VOTE_COMPACT_SMS_PRICE`). 1P=1원.
- 제출 전 인증 문자: 기존 정책인 1P/건 추가. 안내 문자 가격과 별도이며 유권자에게 받을 비용이 아니라 생성자 계정에서 사용한다.
- 간편 템플릿: `moai_vote_compact_v1` / `tpl_b60ac268cfff`, notifier `openvote` 앱에 등록. 기존 투표안내 템플릿은 그대로 둔다.

```text
[모아이투표] {title}
https://vote.bluerdot.net/
코드: {code}
```

- 편집 가능 본문은 제목 하나뿐. 코드 값은 서버가 생성하며 주소·본문·템플릿 이름을 클라이언트가 바꾸지 못한다.
- 고정 부분은 EUC-KR 54바이트. 제목은 남은 36바이트(한글 18자, 영문/숫자 36자) 이내여야 한다. 혼합 제목은 바이트로 검사한다.
- UTF-8 길이로 계산하지 않는다. Python EUC-KR의 한글 2350자와 허용 기호를 공유 자료로 만들었으며 비지원 문자·링크·전화번호·이모지를 거부한다. 초과 시 LMS 자동 전환 없이 차감·코드 회전·발송 전에 거부한다.
- 간편 문자에는 개인 링크가 없다. 생성자가 투표 방법을 별도로 공지한 경우에 쓰라는 설명과 예시를 발송 창에 표시한다.

## 과금·실패 처리

- `createBilledElection`은 기존 생성 RPC에 단가 0을 넘긴다. 실제 생성 RPC도 잔액 0에서 성공하며 포인트는 줄지 않는다. UI의 생성 잔액 차단을 제거했다. 외부 노조링크 연동은 기존처럼 비활성 상태이며 그 과거 계약은 변경하지 않는다.
- 인증된 예상 비용 GET은 대상 수·잔액·형식별 단가·지금 필요한 금액만 반환한다. 공개 사용자는 조회하지 못한다.
- `sms_reserve`: 전체 대상의 비용을 한 트랜잭션에서 예약한다. 부족하면 한 명도 발송하지 않는다. 실제 공급자 호출은 예약 성공 이후에만 한다.
- `sms_dispatches`: 발송 예약·결과·가격을 관리한다. 투표지/선택/영수증/체인 약정을 넣지 않는다. RLS 활성, 서비스롤 전용.
- 잠금 순서: 선거 → 정렬한 명부 행 → 포인트 계정. 명부당 pending/unknown 예약은 하나만 허용한다.
- `sms_settle`/`sms_settle_many`: sent는 사용 확정, failed는 예약액을 정확히 한 번 반환하고 재발송 횟수를 복구한다. 확정 실패만 이전 링크/코드를 복구한다.
- 제공자 타임아웃·5xx·빠진 수신 결과 등은 unknown으로 보류한다. 자동 환불·자동 재발송하지 않는다. 해당 명부의 추가 발송은 막고 운영자에게 확인을 안내한다.
- 미처리 나머지 묶음은 취소·반환한다. 정산 RPC 자체가 실패하면 중복 환불을 피하려고 예약 상태를 보존한다. 운영자가 공급자 결과를 확인한 뒤 서비스롤 정산 함수를 사용할 수 있으나 UI에서 임의 해제하는 기능은 만들지 않았다.
- 이전 선차감 선거의 미발송 유권자는 기존 vote_creation 원장에서 1인 크레딧을 계산해 사용한다. 이전 30P 선차감 후 첫 간편 10P 발송 성공은 20P를 한 번 반환한다. 새 무료 생성은 원장에 선차감액이 없으므로 적용되지 않는다. 이미 발송한 대상에는 다시 인정하지 않는다.
- 본인 재발송은 1회, 관리자 개별 재발송은 5회 제한을 유지한다. 본인 분실 재발송은 기존 안내 형식을 유지하며 명부 여부와 상관없이 동일 응답을 반환한다.
- 1000명 Data API 기본 응답 한도에 걸리지 않도록 명부는 500명씩 조회한다. 매 묶음 전 중단·마감 여부를 확인한다.

## 검증

- 단위 검사 109/109 통과. 한글 18/19자, 영문 36/37자, 90바이트 경계, 비지원 EUC-KR 문자, 변조된 형식 입력을 포함한다.
- `scripts/test-sms-dispatch-service.mjs`: DB·제공자를 모의 처리해 전용 템플릿/변수, 초과 제목의 사전 차단, 잔액 부족 시 코드 회전·발송 없음, 실패 복구, 응답 불명 보류를 확인했다.
- `npm run test:audit-db`: 격리 PostgreSQL 17에서 마이그레이션 2회, 권한 기준선, 전체 잔액 부족 시 예약 0건, 동시 요청의 한 번 예약, 실패 환불 한 번, unknown 차단, 본인 재발송 제한, 기존 선차감 차액 반환, 잔액 0의 무료 생성 통과.
- `MOAI_TEST_HTTP=1 npm run test:audit-db`: 기존 실제 Next API → 격리 REST/SQL → 확인증 → 마감 검증 흐름도 통과.
- ESLint·TypeScript·Next.js 16.4.3 로컬/원격 빌드 통과. `npm audit --omit=dev` 0건.
- 실제 휴대폰 수신·과금과 로그인 후 실제 브라우저 발송 클릭은 시험하지 않았다. 운영에는 시험 선거·기표·발송 예약·메시지를 만들지 않았다.

- notifier HTTPS 헬스체크 200, 인증/간편 템플릿 모두 SMS·활성·각각 code / title,code 변수임을 다시 확인했다. 최종 DB는 선거 1개·투표 1개·발송 예약 0개, 권한 위반 없음이다.
- 간편 템플릿은 서버 기존 관리 함수를 통해 등록했으며 다른 서비스·템플릿·설정은 변경하지 않았다. 추가 인증 템플릿도 실제 발송 없이 존재·활성 상태를 확인한다.
- 운영 데이터나 마이그레이션 이력을 삭제해 롤백하지 않는다. 구버전 코드는 생성 시 선차감하므로 되돌릴 때 무료 생성 정책과 예약 기능의 호환성을 확인해야 한다. unknown/pending은 자동 초기화하지 않는다.
