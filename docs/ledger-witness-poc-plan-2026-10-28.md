# B-1 격리 실험 계획 — 기존 투표 엔진 우선 평가

> **최신 확정 계획:** [v1.0 기존 서비스 기반 경량 감사 계획](voting-native-audit-plan-2026-10-28.md)이 우선한다. Belenios 도입과 운영자 비신뢰 B-1 연구는 보류하고, 기존 모아이에 표준 해시·서명·숨김 약정·공개 집계 재검증을 추가한다. 아래는 과거 검토 기록이며 현재 구현 완료를 뜻하지 않는다.

- 작성: 2026-10-28
- 상태: **문헌·소스 배포 정보 확인 및 실험 계획 작성 완료. 설치·실행·부하 시험은 아직 수행하지 않음.**
- 대상: [설계안 v0.7](ledger-witness-design-2026-10-28.md)
- 목적: 암호 구성요소를 직접 조립하기 전에 기존 시스템이 B-1 요구를 충족하는지 확인한다.
- 범위: 신규 격리 실험. 운영 도메인·DB·명부·계정·문자 발송·실제 자격증명·기존 투표 기능을 사용하지 않는다.

## 1. 결정과 미결을 분리

### 이번 설계에서 결정한 것

1. 첫 실험은 **단일 선택·다중 선택·항목별 찬반**만 다룬다. 신규 B-1 실험에서 Borda는 보류한다. 브라우저 연산이 불가능하다고 입증돼서가 아니라, 검증된 구현·운영 범위를 먼저 좁히기 위해서다. 기존 rank 기능은 변경하지 않는다.
2. Belenios를 우선 평가한다. 채택·운영 출시 결정은 아니다.
3. 엔진의 암호 프로토콜·자격 서명·직렬화를 변경하지 않고, 원래 검증 도구와 자료를 먼저 사용한다.
4. 엔진에 체인이 있으면 별도의 중복 체인을 먼저 만들지 않는다. 모아이 확인증과 원래 tracker·이벤트 기준점의 대응을 검토한다.
5. 보관자의 키 생성·집계 확인·복호화는 모아이 서버가 내려준 임의 웹 JS와 분리한 도구 경로로 평가한다.
6. 외부 게시·저장소 공개 전환·AGPL 적용 범위의 법적 결론·유료 발송은 실행하지 않는다.

### 실험 시작 전 점검할 것

- 고정할 엔진 버전·커밋·소스 서명·의존성과 알려진 보안 수정 현황.
- 분리된 자격 발급자와 집계 키 보관자 역할을 테스트 환경에서 재현할 방법.
- 원래 재투표 정책과 모아이의 1인 1회 정책의 차이. 검증기를 바꾸지 않고 지원 가능한 설정인지 확인한다.
- 검증 도구·키 보관자 도구가 어떤 입력·앵커·상태를 실제로 확인하는지.
- 배포·빌드 환경의 격리 가능 여부와 선택한 도구의 라이선스.

## 3. 비교할 구성

```text
모아이(선거 안내·UX·공개 자료 링크)
  └─ Belenios 격리 서비스(기표·기록·공식 검증 자료)

별도 자격 발급 환경 → 가상 유권자에게만 비밀 자격 전달
                     → 엔진에는 필요한 공개 자격 자료만 전달

독립 경로로 고정한 보관자 도구 → 공개 자료를 스스로 검사
                             → 승인된 최종 집계만 부분 복호화

공식 검증기 + 모아이 연결 계층 검사 → 공개 원장·결과 대조
```

동일 PC에서 프로세스·임시 사용자·경로를 나누는 것은 개발 재현일 뿐 실제 운영 독립성의 실증은 아니다. 운영자가 모든 테스트 키를 알 수 있는 하네스는 편의상 사용할 수 있지만 이를 비밀성 시험 통과로 표시하지 않는다.

모아이 안내 페이지나 백엔드가 비밀 자격·개인 암호화 난수·키 지분을 대신 받지 않게 해야 한다. 실제 통합 API·직렬화·기표 UI를 바꿀 경우 본 실험과 별도 보안 검토를 거친다.

## 4. 실험 단계와 산출물

| 단계 | 수행 | 산출물 | 중단 조건 |
|---|---|---|---|
| P0 후보 적합성 | 고정 릴리스·보안 변경·라이선스·설치 문서·정책 차이 확인 | 버전/해시·보안 미결 목록·라이선스 검토 항목 | 알려진 위험·지원 공백을 판단할 근거 부족 |
| P1 원형 실행 | 합성 유권자로 세 방식의 선거 생성·기표·집계·공식 검증 | 원본 공개 archive·설정·검증 출력 | 역할 분리·정상 집계 불가 |
| P2 악성 입력 | 아래 공격 벡터를 원형 도구에 적용 | 벡터별 예상/실제 결과 | 복사 표·무효 증명·가짜 자격이 통과 |
| P3 보관자 통제 | 독립 도구·고정 최종 집계·재시작 상태·부분합 거부 | 보관자 승인/거부 기록 | 서버 제시 암호문을 그대로 복호화 |
| P4 모아이 연결 | 원래 tracker·체인 기준점·공개 자료를 읽는 최소 어댑터 평가 | 바이트 보존·대응 검사·확인증 형식 초안 | 원형 증명/서명 무효화·새 비밀 전달 경로 |
| P5 UX/성능 | 실제 모바일·네트워크 단절·서명 장애·마감 경합 시험 | 기기/입력별 시간·메모리·크기·복구 기록 | 허용 UX·자격 보존·확정 일관성 실패 |

P0를 통과하기 전 자체 암호 포팅이나 새로운 군/증명 조합을 만들지 않는다. Wasm·Rust·표준 원시 연산 사용만으로 전체 프로토콜이 검증된 것은 아니다. 선택 프로토콜의 실제 벡터와 도구로 검증한다.

## 5. 필수 공격 벡터

### 추가 정책: 선택형 기표 직전 문자 인증

설계안 v0.7 §6.1의 생성자 옵션을 P4 연동 평가에 포함한다. P1~P3의 원형 엔진 평가와 구분하며, 실제 SMS 게이트웨이 대신 모의 발송기를 사용한다. 문자 인증은 독립 비밀 자격을 대체하지 않는다. 모아이 발송 경로에는 비밀 자격을 넣지 않는다.

| ID | 입력·사건 | 확인할 판정 |
|---|---|---|
| O01 | 필수/해제 선거에서 제출 | 필수이면 마지막 단계 새 문자 인증, 해제이면 기본 인증·자격 검사 유지 |
| O02 | 인증 없이 엔진 직접 호출·다른 API로 제출 | 접수 경계에서 거부. UI 검사만으로 통과 처리하지 않음 |
| O03 | 만료·오입력·다른 선거/주체/기표문의 승인 재사용 | 전부 거부하며 선택 평문은 인증 경로에 없음 |
| O04 | 재발송 후 이전 번호 사용·반복 실패 | 이전 번호 거부, 실패 횟수 유지, 발송/검증 제한 적용 |
| O05 | 동시 제출·승인 재사용·커밋 후 응답 유실 | 1회 확정, 동일 기록 재조회는 문자 재발송 없이 복구 |
| O06 | 번호 누락·발송 실패·마감 경과·시작 후 정책 해제 | 자동 우회·번호 대체·마감 연장 없이 명확한 실패 안내 |
| O07 | 모아이/SMS 로그·발송 아웃박스만 확보 | 독립 비밀 자격 복원 불가. 인증번호·평문 선택·키 지분 미기록 |

모의 시험 통과는 실제 단말 수신·통신사 장애·과금·발송 제공자 로그 점검을 대신하지 않는다. 실제 연동 전에는 확정 기표문과 인증 승인 결합, 마감 경계, 번호 정정 권한을 별도 검토한다.

## 6. 보관자 승인 대상과 복호화 오라클 방지

키 보관자 도구는 원래의 공개 데이터와 버전 고정 검증기를 사용해 다음을 독립적으로 확인해야 한다.

1. 고정 선언문·키·자격 목록·선거 상태와 원장의 유효성.
2. 원래 재투표·가중치·무효 규칙을 적용한 최종 유효 집합.
3. 그 정확한 집합으로 직접 계산한 집계 암호문.
4. 사전에 합의·외부 보존한 최종 데이터 digest와 동일한 대상인지.
5. 이 선거·키 세대에서 이미 승인한 대상과 모순되지 않는지.

요청에 붙은 hash/서명만 보고 신뢰하지 않는다. **계산 결과와 암호문이 같다는 조건만으로도 부족하다.** 서로 다른 최종 분기를 보관자별로 제시하는 공격을 막도록 같은 최종 자료에 대한 확인 절차를 평가한다. 임계치가 있다는 사실만으로 분기 합의까지 생기지 않는다.

선거당 ‘네트워크 호출 한 번’이 아니라 **승인된 한 최종 대상에만** 복호화를 허용한다. 동일 대상의 통신 재시도는 가능해야 한다. 보관자 기록의 재시작·복원 후 유지와, 집계 입력이 바뀐 재요청 거부를 시험한다. 공모 정족수는 여전히 경계 밖 위험이다.

## 7. 재투표·확인증·검증기의 통합 조건

Belenios의 마지막 표 집계와 모아이의 기존 1인 1회 정책은 같지 않다. PoC에서는 원래 재투표 동작을 측정·검증하되, 제품의 허용 여부는 별도 결정한다. 앞단에서 버튼만 숨겨 재투표를 막았다고 간주하지 않는다.

원래 이벤트 수에는 Setup·Ballot·집계·복호화·Result가 들어갈 수 있고, 같은 자격의 여러 Ballot도 존재한다. 따라서 `전체 이벤트 수 = 최종 표 수 = 소비 수`라는 단순 불변식을 그대로 옮기지 않는다. 원래 규칙으로 계산한 유효 자격 수·최종 선택 표 집합·집계 입력 수를 비교한다.

개인 파일에는 암호화 난수·복호화 키·비밀 자격을 기본 보관하지 않는 방향이다. 원래 tracker·선거 fingerprint·기록 위치·기준점의 공개 검증 자료를 우선 사용한다. 기록 포함과 기표 의도는 구분하며, 원형 tracker에 서버 서명이 있는지·과거 헤드의 발급 증거가 있는지는 별도 확인한다. 없다면 이를 있다고 표시하지 않는다.

서명된 모아이 확인증이 추가로 필요하면 엔진 자료의 정확한 원본 digest에 결합하는 얇은 어댑터로 한정하고 그 경계를 재검토한다. 암호화 방식·원본 archive 바이트·자격 서명을 다시 정의하지 않는다.

모아이 도구가 공식 검증기를 호출하거나 같은 코어를 사용하면 **독립 구현 두 개의 교차 검증이 아니다.** `공식 프로토콜 검증 결과`와 `모아이 포맷/연결 계층 검사`를 구분해 기록한다. 완전히 독립된 검증기 구현 여부는 별도 산출물이다.

## 8. 웹 코드·라이선스·범위에 대한 정정

### 후속 검토에 따른 확인 사항

- 3.3.0과 개발판의 Fiat–Shamir·키 생성 변경 영향은 소스 diff로 확인한다. 다중 Single 보관자(n-of-n)와 Pedersen 임계 모드는 비교 후보이지 취약점 회피가 증명된 안전 구성은 아니다. 합성 실행 결과로 운영 버전의 안전성을 승인하지 않는다.
- 원형 tracker의 포함 확인과 서버의 접수 승인 증거를 구분한다. 원형 서버 체크포인트 서명이 존재한다고 전제하지 않는다. 추가 서명 어댑터라면 공개 archive에서 실제 Ballot 이벤트를 확인한 뒤 선거 fingerprint·height·이벤트 hash·tracker를 묶고 **모아이 키의 별도 증언**임을 표시한다. 원형 서명을 추출한 것처럼 표시하거나 중복 체인을 만들지 않는다.
- 1인 1회 모드의 엔진 재투표 거부 설정을 고정 버전 소스로 확인하고 직접 접수 경로에서도 시험한다. 별도로 전체 Ballot 이력의 자격 중복을 정책 검사하되, 동일 기표문 재요청과 다른 기표문 재투표를 구분한다. 공개 자격을 삭제하여 과거 서명 검증을 깨뜨리지 않는다. 원형 last(B) 검증 통과와 모아이 정책 통과는 별개다.
- 질문별 min/max/blank와 모아이 기권의 매핑 표를 만든다. 특히 항목 일부 기권과 투표지 전체 기권은 다르다. 0개 선택, 명시적 blank, min=0/1 경계값을 각각 시험한다. 정확히 표현하지 못하는 설정은 B-1 미지원으로 남긴다.
- 공식 CLI 호출, 독립 파서의 포맷/연결 검사, 별도 구현의 암호 증명 검증을 서로 다른 범위로 보고한다. 독립 파서 성공만으로 독립 암호 검증 완료라고 쓰지 않는다.
- 측정 전 제품 UX 목표를 고정한다. 답 수·유효한 min/max 조합·질문 수·기기/브라우저·표 100/1,000/10,000건을 기록하고 생성/전송/접수/확인증 시간을 분리한다. 외부 검토의 2.5초·50MB는 아직 채택하거나 실측한 기준이 아니다.
- AGPL의 실제 LICENSE·예외 문구와 수정/배포/결합 형태를 검토한다. API 사용이 자동 면제라는 결론도, 네트워크 연결만으로 모아이 전체 공개 의무가 확정된다는 결론도 내리지 않는다.

- CSP/SRI/재현 빌드는 유용한 방어·감사 수단이지만 운영자가 HTML·정책·키를 함께 바꾸면 그 자체로 신뢰 앵커가 되지 않는다. 같은 origin 유출과 요청 자체 변조도 검토한다.
- 서비스 워커/PWA나 앱스토어 배포만으로 신뢰가 사라지지 않는다. 업데이트·서명·배포 주체를 따로 정해야 한다.
- 검토문의 ‘어떤 브라우저 라이브러리도 존재하지 않는다’, ‘50개 암호문이면 연산 불능’, ‘Rust/Wasm 라이브러리는 형식 검증됐다’는 포괄적 주장은 채택하지 않는다. 실제 프로젝트·버전·감사 범위·기기 측정으로 판단한다.
- 순위 보류는 합리적인 첫 실험 범위 조정이다. 암호학적 불가능성 또는 기존 rank 삭제 결정이 아니다.
- 기권 비트 A와 `q[min]+A=1`만으로는 A=1인데 1~min-1개 선택을 한 경우를 배제하지 못할 수 있다. `A=1 → 모든 선택 0` 조건을 함께 유지해야 한다. 이 논의는 후속 순위 규격용이며 첫 실험에는 포함하지 않는다.
- AGPL 소스 제공 범위·모아이와의 결합·수정 도구 배포 의무는 실제 구성으로 검토한다. 서비스 분리가 곧 라이선스 예외라고 결론 내리지 않는다.

## 9. 실험 완료 시 제출할 보고서

- 고정 버전/커밋·소스/빌드 검증과 남은 보안 변경 영향.
- 실제 분리한 역할·키 접근 경로·가상 데이터 생성 방법.
- 벡터별 예상/실제 결과와 실패 원본, 개인정보·비밀을 제외한 공개 archive.
- 원형 정책과 모아이 요구의 차이, 어댑터가 추가하는 신뢰 경계.
- 실제 기기·표 수·후보 수·증명/파일 크기·시간·메모리 측정.
- 원형 도구가 검사한 것과 모아이 도구가 검사한 것의 구분.
- `채택 후보 유지 / 필수 보완 후 재평가 / 부적합` 판정과 운영 비용·미결 정책.

이 보고서가 나오기 전 상태는 **PoC 계획 수립**이지 PoC 통과·설치 완료·출시 가능이 아니다.
