# 최근 종료된 공개 투표 홈 표시

## 사용자 동작

- 공개 투표 홈 목록에 진행 중인 투표와 최근 종료 투표를 표시한다. 진행 중인 투표가 먼저 나오고, 종료 투표는 최근 종료순이다.
- 기본값은 종료 후 7일이다. 생성자는 `내 투표 관리 → 해당 투표 → 종료 후 홈 표시`에서 0~365일로 수정한다. 0일은 종료 직후 홈에서 숨긴다. 관리자도 기존 관리 권한 범위에서 수정할 수 있다.
- 기간이 지나도 결과를 삭제하지 않으며 기존 링크로 열 수 있다. 휴지통 투표·준비중·일시중단 상태는 홈에서 제외한다.
- 자동 마감이 늦게 처리되어도 예약된 마감일을 기준으로 한다. 조기 수동 종료는 실제 종료 시각을 기록한다. 이후 설정 변경으로 종료 시각이 갱신되지 않게 고정한다.
- 기존 종료 투표는 과거 정확한 조기 종료 시각을 저장하지 않았으므로, 기존 마감일(없으면 최종 변경일)을 기준으로 보완했다.

## 구현과 검증

- CLI로 생성한 `20261029205953_home_closed_elections.sql`(UTC 파일 시각)은 `app_open_vote.elections`에 `home_closed_days`·`closed_at`, 종료 시각 트리거, 제한된 홈 요약 조회 함수를 추가한다. 권한은 service_role 전용이며 기준선 위반 0건이다. 다른 앱·공유 Auth 변경 없음.
- 종료 상태·제목·번호·참여율만 카드에 전달한다. 후보·선택·유권자 정보를 공개 요약에 복사하지 않는다. 동시 통계 조회 최대 4개를 유지한다.
- 설정은 기존 생성자 인증 및 선거 소유권 검사 후 허용한다. 숫자 정수 0~365만 허용하고 휴지통 상태에서는 저장하지 않는다. 선거 규칙·서명 선언문·집계와 별개의 표시 설정이다.
- 단위 테스트 119개, ESLint, TypeScript와 프로덕션 빌드 통과.
- 격리 PostgreSQL: 두 번 적용, 기본 7일, 사용자 지정·0일 숨김, 만료 경계, 자동/조기 종료, 휴지통·준비중·중단 제외, 범위·권한 기준선 검증 통과. 초기 시험의 휴지통 직접 변경은 기존 보호 트리거가 거부했으며, 정상 RPC를 사용하도록 시험을 수정해 통과했다.
- 운영 홈에서 기존 종료 투표 1개의 종료 카드·결과 안내를 확인했다. 현재 로그인 생성자 계정에는 투표가 없어 관리 폼의 실제 저장은 브라우저에서 시험하지 않았다. 가짜 인증·DB를 주입한 실제 라우트 시험과 격리 SQL 시험으로 검증한다.
